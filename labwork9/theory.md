## 0. Основа

### Сервер не помнит пользователя

Браузер и сервер общаются **запросами**:

1. браузер просит страницу (**запрос**);
2. сервер запускает PHP-скрипт и отправляет результат (**ответ**);
3. всё — разговор окончен.

Следующий запрос сервер обрабатывает **с нуля**. Он не знает, что это тот же человек, который секунду назад выбрал язык. Каждый запуск PHP-скрипта тоже начинается с чистого листа: все переменные прошлого запуска исчезли.

Чтобы связать запросы одного человека между собой, есть два механизма — **куки** и **сессии**.

### Ответ сервера: заголовки и тело

Ответ сервера состоит из двух частей:

1. **Заголовки** (headers) — служебная информация: тип содержимого, команды «сохрани куку», «перейди на другую страницу».
2. **Тело** — сам HTML, который видно на странице.

Заголовки всегда отправляются **первыми**. Как только PHP вывел хоть один символ тела — `echo`, HTML-текст, даже пустую строку перед `<?php` — заголовки уже ушли, и добавить к ним ничего нельзя.

Отсюда **главное правило лабы**: функции, которые работают с заголовками, — `session_start()`, `setcookie()`, `header()` — должны вызываться **в самом начале файла, до любого вывода**. Иначе — предупреждение `headers already sent`, и функция не сработает.

Поэтому во всех файлах лабы работа с сессией стоит в блоке `<?php ... ?>` **перед** `<html>`.

### Кука

**Кука** (cookie) — маленькая запись «имя = значение», которую сервер просит браузер сохранить. Дальше браузер **сам** прикладывает её к каждому запросу на этот сайт:

```
ответ сервера:    Set-Cookie: PHPSESSID=ggpf1lg574jd3n3r80junou873; path=/
следующий запрос: Cookie: PHPSESSID=ggpf1lg574jd3n3r80junou873
```

- хранится **у пользователя**, в браузере — он может её посмотреть, удалить или подделать;
- маленькая — около 4 КБ;
- имеет срок жизни; если срок не задан — живёт до закрытия браузера.

### Сессия

**Сессия** — хранилище данных о пользователе **на сервере**:

1. PHP придумывает случайный **идентификатор** (id) сессии, например `ggpf1lg574jd3n3r80junou873`, и создаёт на сервере файл для данных.
2. id отправляется браузеру **в куке** с именем `PHPSESSID`.
3. В скрипте данные кладутся в массив `$_SESSION`.
4. При следующем запросе браузер присылает куку `PHPSESSID`, и PHP по ней находит **тот же файл**.

Аналогия — **гардероб**. Пальто (данные) висит в гардеробе (на сервере), а у тебя на руках только номерок (кука с id). По номерку тебе выдают именно твоё пальто. Потеряешь номерок — пальто останется висеть, но получить его уже не сможешь.

| | Куки | Сессия |
|---|---|---|
| где хранятся данные | в браузере | на сервере |
| что лежит в браузере | все данные | только id сессии |
| может ли пользователь подделать данные | да | нет, только id |
| объём | ~4 КБ | ограничен только сервером |
| как обратиться в PHP | `$_COOKIE` | `$_SESSION` |

### Суперглобальные массивы

В ЛР8 был `$GLOBALS` — **суперглобальный** массив, видный в любом месте программы, даже внутри функций. В этой лабе их ещё пять. Все они заполняются **автоматически** — PHP сам кладёт в них данные запроса:

| Массив      | Что в нём                      | Откуда берётся                                          |
| ----------- | ------------------------------ | ------------------------------------------------------- |
| `$_GET`     | параметры из адреса страницы   | `page.php?action=start` → `$_GET["action"]` = `"start"` |
| `$_POST`    | данные формы с `method="post"` | `<select name="lang">` → `$_POST["lang"]`               |
| `$_COOKIE`  | куки, которые браузер прислал  | `$_COOKIE["PHPSESSID"]`                                 |
| `$_SESSION` | данные текущей сессии          | заполняется после `session_start()`                     |
| `$_SERVER`  | информация о запросе и сервере | `$_SERVER["REQUEST_METHOD"]` = `"GET"` или `"POST"`     |

Каждый подробно разобран ниже, в том задании, где он впервые используется.

### Где в браузере найти куки

**Chrome:** правый клик по странице → «Просмотреть код» (`Cmd + Option + I` на Mac, `F12` на Windows) → вкладка **Application** (если её не видно — она прячется за `>>`) → в левом меню **Storage → Cookies** → адрес сайта (`http://localhost:...`).

Справа — таблица кук этого сайта:

| Столбец | Что значит |
|---|---|
| Name | имя куки — `PHPSESSID` |
| Value | значение — id сессии |
| Domain, Path | для какого сайта и какой его части кука: `localhost`, `/` — для всего сайта |
| Expires / Max-Age | когда истекает; `Session` — до закрытия браузера |
| Size | размер в байтах |
| HttpOnly, Secure, SameSite | настройки безопасности куки |

Таблица обновляется сама. Куку можно удалить вручную: правый клик по строке → Delete.

### `$_GET` — параметры из адреса

```php
$action = $_GET["action"] ?? "";
```

Всё, что стоит в адресе после `?`, — **параметры запроса**. Записываются парами `имя=значение`, несколько пар — через `&`:

```
task1.php?action=start
task1.php?action=start&lang=be
```

PHP сам разбирает адрес и кладёт параметры в массив `$_GET`:

```php
// адрес: task1.php?action=start&lang=be
$_GET["action"];  // "start"
$_GET["lang"];    // "be"
```

Значения в `$_GET` **всегда строки** — даже `?page=5` даст строку `"5"`.

Если параметра в адресе нет, ключа в массиве тоже нет. Обращение `$_GET["action"]` дало бы предупреждение `Undefined array key`. Поэтому стоит `?? ""` — оператор из ЛР8: «если такого ключа нет — взять пустую строку».

В `task1.php` четыре ссылки ведут на эту же страницу с разными `?action=...`. Так одна страница умеет делать четыре разных действия.

### `session_start()` — открыть сессию

```php
session_start();
```

Открывает сессию. Делает одно из двух:

- **браузер прислал куку `PHPSESSID`** и файл с таким id есть на сервере → **продолжить** старую сессию: прочитать файл и заполнить `$_SESSION` сохранёнными данными;
- **куки нет** (или файла с таким id нет) → **создать** новую сессию: придумать id, создать пустой файл и добавить в ответ заголовок `Set-Cookie: PHPSESSID=<id>`.

Возвращает `true`, если всё получилось, и `false` при ошибке — например, если до него уже был вывод:

```
Warning: session_start(): Session cannot be started after headers have already been sent
```

Важно:

- вызывать **до любого вывода**;
- вызывать **на каждой странице**, где нужен `$_SESSION`. Без него `$_SESSION` пуст, даже если сессия существует.

### `session_id()` — узнать идентификатор

```php
echo session_id();  // 1uoe1laceh96o0jsae83l20lcn
```

Без аргументов возвращает id текущей сессии — тот самый «номерок». Если сессия не открыта — пустую строку `""`.

С аргументом умеет и **задать** id — это разобрано в задании 2.

### `session_name()` — узнать имя сессии

```php
echo session_name();  // PHPSESSID
```

Без аргументов возвращает **имя** сессии. Оно же — имя куки, в которой хранится id. По умолчанию `PHPSESSID`.

С аргументом умеет и **задать** имя — это тоже в задании 2.

### `session_destroy()` — уничтожить сессию на сервере

```php
session_start();
$_SESSION = [];
session_destroy();
```

Удаляет **файл сессии на сервере**. Возвращает `true` при успехе.

Три важных момента:

1. **Уничтожить можно только открытую сессию.** Без `session_start()` перед ним будет `Warning: Trying to destroy uninitialized session` и `false`. Сначала сессию нужно «найти» по куке.
2. **`$_SESSION` в текущем скрипте он не очищает.** Файл удалён, но уже заполненный массив дожил бы до конца скрипта. Поэтому перед ним стоит `$_SESSION = []` — присвоить пустой массив.
3. **Куку в браузере он не трогает.** Браузеру он ничего не отправляет — кука `PHPSESSID` остаётся. Это ответ на вопрос «почему после завершения сессии кука осталась».

### `setcookie($имя, $значение, $срок, $путь, $домен, $secure, $httponly)` — поставить или удалить куку

```php
setcookie("theme", "dark", time() + 3600);   // поставить куку на час
setcookie("theme", "", time() - 3600);       // удалить куку
```

Добавляет в ответ заголовок `Set-Cookie` — просит браузер сохранить куку.

| Аргумент    | Что значит                                                                     | Обязательный           |
| ----------- | ------------------------------------------------------------------------------ | ---------------------- |
| `$имя`      | имя куки                                                                       | да                     |
| `$значение` | что сохранить (строка)                                                         | нет, по умолчанию `""` |
| `$срок`     | до какого момента хранить, в секундах от 1970 года; `0` — до закрытия браузера | нет, по умолчанию `0`  |
| `$путь`     | для какой части сайта: `/` — для всего                                         | нет                    |
| `$домен`    | для какого домена                                                              | нет                    |
| `$secure`   | отправлять только по HTTPS                                                     | нет                    |
| `$httponly` | не давать JavaScript читать куку                                               | нет                    |

Возвращает `true`, если заголовок удалось добавить, и `false`, если вывод уже был (`Cannot modify header information - headers already sent`).

**Удалить куку отдельной командой нельзя.** Удаление — это та же `setcookie` со сроком **в прошлом**: браузер видит, что кука уже истекла, и сам её стирает.

**Удаляет только куку с тем же путём и доменом.** Если кука ставилась для `path=/`, а удалять её с другим путём, браузер посчитает это другой кукой, и исходная останется.

`setcookie` действует только на **следующий** запрос: в текущем `$_COOKIE` новая кука не появится (см. «Нюанс» ниже).

### `time()` — текущее время в секундах

```php
echo time();          // 1793277600
echo time() + 3600;   // через час
echo time() - 3600;   // час назад
```

Возвращает количество секунд, прошедших с 1 января 1970 года (это называется **Unix-время**). Сроки кук задаются именно в таком формате, поэтому «через час» — это `time() + 3600` (3600 секунд = 60 минут).

### `session_get_cookie_params()` — с какими параметрами ставилась кука сессии

```php
print_r(session_get_cookie_params());
```

```
Array
(
    [lifetime] => 0        // срок: 0 — до закрытия браузера
    [path] => /            // путь
    [domain] =>            // домен
    [secure] =>            // только HTTPS
    [httponly] =>          // недоступна JavaScript
    [samesite] =>
)
```

Возвращает массив параметров, с которыми PHP ставит куку `PHPSESSID`. Нужен, чтобы удалить эту куку с **теми же** путём и доменом.

### `$_COOKIE` — куки, присланные браузером

```php
print_r($_COOKIE);
// Array ( [PHPSESSID] => 1uoe1laceh96o0jsae83l20lcn )
```

Массив кук, которые браузер приложил **к текущему запросу**. Ключ — имя куки, значение — её значение.

### Как это собрано в `task1.php`

Вся логика стоит **до** `<html>`, цепочкой `if / elseif` (ЛР7):

```php
$action = $_GET["action"] ?? "";

if ($action === "start") {
    session_start();
    $_SESSION["opened_at"] = date("H:i:s");
    $message = "сессия открыта, id: " . session_id();
} elseif ($action === "destroy") {
    session_start();
    $_SESSION = [];
    session_destroy();
} elseif ($action === "delete_cookie") {
    session_start();
    $_SESSION = [];
    $params = session_get_cookie_params();
    setcookie(session_name(), "", time() - 3600, $params["path"], $params["domain"], $params["secure"], $params["httponly"]);
    session_destroy();
}
```

Удаление куки разбираем по аргументам:

- `session_name()` — имя куки, которую удаляем: `PHPSESSID`;
- `""` — значение больше не нужно;
- `time() - 3600` — срок истёк час назад → браузер стирает куку;
- `$params["path"]`, `$params["domain"]`, … — те же параметры, с которыми куку ставили.

Это стандартный способ удаления сессии вместе с кукой из документации PHP.

### Четыре этапа — что на скриншотах

| № | Что нажали | Что сервер отправил браузеру | Кука `PHPSESSID` в DevTools |
|---|---|---|---|
| 1 | ничего, первый заход | ничего про куки | **нет** |
| 2 | «Открыть сессию» | `Set-Cookie: PHPSESSID=<id>` | **появилась** |
| 3 | «Завершить сессию (только session_destroy)» | ничего про куки | **осталась**, то же значение |
| 4 | «Завершить сессию и удалить куку» | `Set-Cookie: PHPSESSID=deleted; expires=1970…` | **исчезла** |

### Ответ на вопрос задания: почему куки изменились

- **До** `session_start()` сервер ни разу не просил браузер что-то сохранить — кук нет.
- `session_start()` создал новую сессию и добавил в ответ `Set-Cookie: PHPSESSID=<id>`. Браузер выполнил просьбу — кука появилась. Её значение совпадает с id, который вывел PHP.
- Сессия хранит данные на сервере, но браузеру нужно как-то «представляться» при следующих запросах. Для этого PHP и выдаёт ему номерок — куку с id.
- После `session_destroy()` кука **осталась**: функция удаляет только файл на сервере и браузеру ничего не отправляет. В браузере лежит номерок от уже несуществующего пальто. При следующем `session_start()` PHP не найдёт файла с этим id и создаст новую пустую сессию.
- Чтобы исчезла и кука, нужен отдельный `setcookie` со сроком в прошлом (этап 4).

### Нюанс: `$_COOKIE` отстаёт на один запрос

Сразу после «Открыть сессию» `print_r($_COOKIE)` на странице **пустой**, хотя в DevTools кука уже есть. Причина — кука появилась только в **ответе** на этот запрос:

```
запрос 1 (action=start):  Cookie: —                → $_COOKIE пустой
ответ 1:                  Set-Cookie: PHPSESSID=…  → браузер сохранил куку
запрос 2 (обновить):      Cookie: PHPSESSID=…      → $_COOKIE содержит куку
```

Поэтому на странице есть ссылка «Обновить без действий» — после неё кука видна в `$_COOKIE`.

С удалением так же: на странице «удалить куку» `$_COOKIE` ещё показывает старую куку — браузер прислал её до того, как получил команду удалить.

### Почему отдельные страницы

`session_start()` должен стоять в самом начале файла. Если поставить его в `lab9.php`, сессия открывалась бы при каждом заходе на лабу, и в задании 1 не получилось бы увидеть «куки до сессии». Поэтому задание 2 — на своих страницах: `task2.php` записывает, `task2_read.php` читает.

### `session_name($новое_имя)` — сменить имя сессии

```php
session_name("MYSESSION");  // ДО session_start()
session_start();             // теперь кука называется MYSESSION
```

С аргументом задаёт новое имя сессии (то есть имя куки). Возвращает **старое** имя.

Работает **только до** `session_start()`. Если сессия уже открыта:

```
Warning: session_name(): Session name cannot be changed when a session is active
```

и возвращает `false`.

Если сменить имя, это нужно делать на **каждой** странице перед `session_start()`. Иначе другие страницы будут искать куку `PHPSESSID`, не найдут её и создадут новую пустую сессию.

### `session_id($новый_id)` — задать идентификатор

```php
session_id("abc123");  // ДО session_start()
session_start();       // откроется (или создастся) сессия с id abc123
```

С аргументом задаёт id, с которым откроется сессия. Возвращает **старый** id.

Тоже работает **только до** `session_start()`. После:

```
Warning: session_id(): Session ID cannot be changed when a session is active
```

и `false`.

### `@` — оператор подавления ошибок

```php
$renameResult = @session_name("MYSESSION");
```

`@` перед вызовом функции — не выводить на страницу её предупреждения. Функция при этом выполняется как обычно и возвращает своё значение.

Обычно `@` — плохая привычка: он прячет проблемы. Здесь он нужен по конкретной причине. Текст предупреждения — это **вывод**. Если бы он попал на страницу, заголовки ушли бы, и строкой ниже `session_regenerate_id()` уже не смогла бы отправить браузеру новую куку — сама выдала бы `Session ID cannot be regenerated after headers have already been sent`. Отказ видно и без текста предупреждения — по возвращённому `false`.

### `session_regenerate_id($удалить_старую)` — новый id для открытой сессии

```php
session_regenerate_id(true);
echo session_id();  // уже другой id
```

Единственный способ сменить id **уже открытой** сессии. Создаёт новый id, переносит в сессию с ним все данные и отправляет браузеру новую куку. Возвращает `true` при успехе.

Аргумент: `true` — удалить файл со старым id, `false` (по умолчанию) — оставить.

Зачем это в реальной жизни: защита от **фиксации сессии**. Злоумышленник может подсунуть жертве ссылку с заранее известным id. Если после входа в аккаунт id сменить, известный злоумышленнику id станет бесполезным. Поэтому `session_regenerate_id(true)` вызывают сразу после успешного входа.

### Итог «попробуйте изменить эти значения»

```php
session_start();

$oldName = session_name();   // PHPSESSID
$oldId = session_id();       // jislmv0jbgcp91kaet2qsu2s3d

$renameResult = @session_name("MYSESSION");   // false
$changeIdResult = @session_id("vlad123");     // false

session_regenerate_id(true);
$newId = session_id();       // новый id
```

| Что пробуем | Как | Результат |
|---|---|---|
| сменить имя после `session_start()` | `session_name("MYSESSION")` | `false`, имя осталось `PHPSESSID` |
| сменить id после `session_start()` | `session_id("vlad123")` | `false`, id остался прежним |
| сменить id правильным способом | `session_regenerate_id(true)` | id **сменился**, данные сохранились |

### `$_SESSION` — данные сессии

```php
$_SESSION["time"] = date("d.m.Y H:i:s");
$_SESSION["name"] = "Влад";
$_SESSION["age"] = 20;
$_SESSION["subjects"] = [
    "Высокоуровневые языки программирования",
    "Веб-дизайн",
    "Системы управления контентом",
    "Графический дизайн",
];
```

Суперглобальный массив с данными текущей сессии. Работает как обычный ассоциативный массив: записать — `$_SESSION["ключ"] = значение`, прочитать — `$_SESSION["ключ"]`, удалить один ключ — `unset($_SESSION["ключ"])`.

Положить можно строки, числа и даже **массивы** (как `subjects`).

Специально «сохранять» ничего не нужно. Когда скрипт заканчивается, PHP сам записывает `$_SESSION` в файл сессии. Массивы он при этом превращает в строку — **сериализует**, — а при следующем `session_start()` восстанавливает обратно.

`date("d.m.Y H:i:s")` и `date_default_timezone_set("Europe/Minsk")` — текущие дата и время в местном часовом поясе (ЛР8, задание 6).

### `isset($переменная)` — существует ли значение

```php
$a = ["x" => 5, "y" => null];

isset($a["x"]);   // true  — ключ есть, значение не null
isset($a["y"]);   // false — ключ есть, но значение null
isset($a["z"]);   // false — ключа нет
```

Возвращает `true`, если переменная (или элемент массива) **существует и не равна `null`**. Проверка не вызывает предупреждения, даже если ключа нет. Поэтому ей проверяют «можно ли обратиться к этому элементу».

Можно проверить несколько сразу: `isset($a, $b)` — `true`, только если существуют оба.

### Чтение на другой странице — `task2_read.php`

```php
session_start();

if (isset($_SESSION["name"])) {
    echo "время записи:  {$_SESSION["time"]}\n";
    echo "имя:           {$_SESSION["name"]}\n";
    echo "возраст:       {$_SESSION["age"]}\n";
    echo "любимые предметы:\n";
    foreach ($_SESSION["subjects"] as $i => $subject) {
        echo "  ", $i + 1, ". $subject\n";
    }
} else {
    echo "в сессии нет данных — сначала откройте task2.php\n";
}
```

По шагам:

1. `session_start()` — браузер прислал куку `PHPSESSID`, PHP нашёл по ней файл и заполнил `$_SESSION`.
2. `isset($_SESSION["name"])` — есть ли данные. Если зайти на `task2_read.php` первым (или после удаления куки в задании 1), сессия пустая, и без проверки было бы `Undefined array key`.
3. `{$_SESSION["name"]}` — фигурные скобки нужны, чтобы вставить элемент массива со строковым ключом внутрь строки в двойных кавычках (ЛР2, интерполяция).
4. `foreach ($_SESSION["subjects"] as $i => $subject)` — перебор массива предметов (ЛР7). `$i + 1` — нумерация с единицы, а не с нуля.

**Доказательство, что данные пришли из сессии:** время на второй странице совпадает со временем записи, а не с текущим. И `session_id()` на обеих страницах одинаковый — это одна и та же сессия.

## Задание 3 — сайт с выбором языка

> Для передачи данных используйте метод POST.
>
> Создайте связанные файлы (реализуйте через перекрёстные ссылки) с какой-либо текстовой информацией, содержащие в хедере (подключаемом через `require`) форму с полем ввода типа select. Данное поле реализует выбор языка интерфейса. При изменении языка пользователем форма должна отправляться на сервер, данные – записываться в сессию, а текст на всех страницах – отображаться на выбранном языке.

### Устройство сайта

```
task3/
├── lang.php     ← все тексты: $languages и $texts
├── header.php   ← session_start, обработка POST, <head>, меню, форма с select
├── footer.php   ← подвал, закрывающие </body></html>
├── index.php    ← страница «О городе»
├── sights.php   ← «Достопримечательности»
└── food.php     ← «Кухня»
```

Каждая страница устроена одинаково:

```php
<?php require "header.php"; ?>

<h1><?= $t["pages"]["sights"]["title"] ?></h1>
...
<?php require "footer.php"; ?>
```

`require "header.php"` — **первая строка** страницы, до любого HTML: внутри хедера стоят `session_start()` и `header()`, им нужно, чтобы вывода ещё не было.

`require` и `require_once` — подключение файла (ЛР7). `require_once "lang.php"` в хедере подключает тексты один раз.

Хедер и подвал общие для всех страниц — приём из ЛР7, задание 6.

### Тексты — `lang.php`

```php
$languages = [
    "ru" => "Русский",
    "be" => "Беларуская",
    "en" => "English",
];

$texts = [
    "ru" => [
        "choose" => "Язык:",
        "nav" => ["index" => "Главная", "sights" => "Достопримечательности", "food" => "Кухня"],
        "pages" => [
            "index" => ["title" => "О городе", "text" => [...]],
            ...
        ],
    ],
    "be" => [...],
    "en" => [...],
];
```

- `$languages` — какие языки есть: ключ — код языка, значение — как его показать в списке.
- `$texts` — многомерный массив (ЛР2, задание 7). Первый ключ — язык, дальше **одинаковая** структура для всех языков.

Благодаря одинаковой структуре выбор языка — одна строка:

```php
$t = $texts[$lang];   // все тексты на нужном языке
```

Дальше везде `$t["nav"]["index"]`, `$t["pages"]["food"]["title"]` — код страниц от языка не зависит. Чтобы добавить язык, достаточно дописать его в `$languages` и `$texts`.

### HTML-форма: `<form>`, `<select>`, `<option>`

```html
<form method="post">
    <label>
        Язык:
        <select name="lang" onchange="this.form.submit()">
            <option value="ru" selected>Русский</option>
            <option value="be">Беларуская</option>
            <option value="en">English</option>
        </select>
    </label>
</form>
```

| Элемент / атрибут                        | Что делает                                                                    |
| ---------------------------------------- | ----------------------------------------------------------------------------- |
| `<form>`                                 | форма — всё, что внутри, отправляется на сервер одним запросом                |
| `method="post"`                          | отправить методом POST (по умолчанию был бы GET)                              |
| `action="..."`                           | куда отправить; **не указан** → на ту же страницу, где форма                  |
| `<select name="lang">`                   | выпадающий список; `name` — под каким ключом значение придёт на сервер        |
| `<option value="be">Беларуская</option>` | пункт списка: `value` уходит на сервер, текст между тегами видит пользователь |
| `selected`                               | этот пункт выбран, когда страница открылась                                   |
| `<label>`                                | подпись к полю; клик по подписи активирует поле                               |
| `onchange="this.form.submit()"`          | JavaScript: при выборе пункта браузер **сам** отправляет форму                |

Выбрали «Беларуская» → на сервер уходит пара `lang=be` → в PHP она окажется в `$_POST["lang"]`.

`onchange` выполняет требование задания «**при изменении языка** форма должна отправляться». Без него понадобилась бы кнопка «Отправить».

### GET и POST

Оба — способы отправить данные на сервер.

|                                                | GET                                             | POST                                                     |
| ---------------------------------------------- | ----------------------------------------------- | -------------------------------------------------------- |
| где данные                                     | в адресной строке: `page.php?lang=be`           | в теле запроса, в адресе их не видно                     |
| в PHP                                          | `$_GET["lang"]`                                 | `$_POST["lang"]`                                         |
| объём                                          | ограничен длиной адреса                         | большой                                                  |
| можно сохранить в закладки / отправить ссылкой | да                                              | нет                                                      |
| для чего                                       | получить данные: поиск, фильтры, номер страницы | изменить что-то на сервере: вход, регистрация, настройки |

В задании 1 используется GET (`task1.php?action=start`) — это обычные ссылки. В задании 3 — POST, потому что форма меняет настройку пользователя.

### `$_POST` — данные формы

```php
// выбрали "Беларуская" в <select name="lang">
$_POST["lang"];  // "be"
```

Массив данных, отправленных формой с `method="post"`. Ключ — атрибут `name` поля, значение — что пользователь выбрал или ввёл. Значения, как и в `$_GET`, — **строки**.

Если страницу открыли обычным переходом, а не отправкой формы, `$_POST` пустой.

### `$_SERVER` — информация о запросе

Массив, который PHP заполняет данными о текущем запросе и о сервере. В лабе используются три ключа:

| Ключ                         | Что в нём                                          | Пример                       |
| ---------------------------- | -------------------------------------------------- | ---------------------------- |
| `$_SERVER["REQUEST_METHOD"]` | каким методом пришёл запрос                        | `"GET"` или `"POST"`         |
| `$_SERVER["REQUEST_URI"]`    | адрес страницы, как в адресной строке (без домена) | `/labwork9/task3/sights.php` |
| `$_SERVER["SCRIPT_NAME"]`    | путь к выполняемому PHP-файлу                      | `/labwork9/task3/sights.php` |

`REQUEST_URI` включает параметры (`...sights.php?x=1`), `SCRIPT_NAME` — только путь к файлу.

Посмотреть всё содержимое: `print_r($_SERVER)`.

### `array_key_exists($ключ, $массив)` — есть ли ключ в массиве

```php
$languages = ["ru" => "Русский", "be" => "Беларуская", "en" => "English"];

array_key_exists("be", $languages);   // true
array_key_exists("abc", $languages);  // false
```

Возвращает `true`, если в массиве есть такой **ключ**.

Отличие от `isset`: `array_key_exists` возвращает `true`, даже если значение по ключу — `null`. `isset` в этом случае вернёт `false`:

```php
$a = ["x" => null];
isset($a["x"]);              // false
array_key_exists("x", $a);   // true
```

Здесь это проверка «такой язык у нас есть».

### `header("Location: адрес")` — перенаправить браузер

```php
header("Location: sights.php");
```

`header()` добавляет в ответ произвольный HTTP-заголовок. Заголовок `Location` — команда браузеру: «перейди по этому адресу». Браузер тут же сам открывает указанную страницу обычным GET-запросом.

Как и `setcookie`, работает **только до любого вывода**.

### `exit` — остановить скрипт

```php
header("Location: sights.php");
exit;
```

Немедленно завершает выполнение скрипта — всё, что ниже, не выполнится.

После `header("Location")` он обязателен по смыслу: заголовок только *просит* браузер уйти, но PHP продолжил бы выполнять код и выводить страницу, которую никто не увидит.

`exit` можно вызвать и с текстом: `exit("Ошибка")` — вывести текст и остановиться. Его синоним — `die`.

### `basename($путь, $убрать_окончание)` — имя файла из пути

```php
basename("/labwork9/task3/sights.php");          // "sights.php"
basename("/labwork9/task3/sights.php", ".php");  // "sights"
```

Возвращает последнюю часть пути — имя файла, без папок. Если передать второй аргумент, это окончание отрезается (если имя на него заканчивается). В ЛР5 мы получали имя файла через `strrchr` + `substr` — `basename` делает то же одной функцией.

### Тернарный оператор `условие ? если_да : если_нет`

```php
$code === $lang ? "selected" : ""
```

Короткая запись `if / else`, которая **возвращает значение**:

```php
// то же самое через if
if ($code === $lang) {
    $result = "selected";
} else {
    $result = "";
}
```

Удобен, когда нужно выбрать одно из двух значений прямо внутри строки или вывода.

### Как это собрано: начало `header.php`

```php
session_start();
require_once "lang.php";

if ($_SERVER["REQUEST_METHOD"] === "POST" && isset($_POST["lang"]) && array_key_exists($_POST["lang"], $languages)) {
    $_SESSION["lang"] = $_POST["lang"];
    header("Location: " . $_SERVER["REQUEST_URI"]);
    exit;
}

$lang = $_SESSION["lang"] ?? "ru";
$t = $texts[$lang];
$page = basename($_SERVER["SCRIPT_NAME"], ".php");
```

По строкам:

1. `session_start()` — в сессии может уже лежать выбранный язык.
2. `require_once "lang.php"` — подключить тексты.
3. `if` из трёх условий через `&&` — все три должны быть истинны:
   - `$_SERVER["REQUEST_METHOD"] === "POST"` — страницу открыли **отправкой формы**, а не переходом по ссылке;
   - `isset($_POST["lang"])` — в форме действительно был язык;
   - `array_key_exists($_POST["lang"], $languages)` — **такой язык у нас есть**. Данным от пользователя нельзя верить: через DevTools можно отправить `lang=abc`. Без проверки дальше было бы `$texts["abc"]` → ошибки на всех страницах.
4. `$_SESSION["lang"] = $_POST["lang"]` — запомнить язык **в сессии**. Поэтому он сохраняется на **других** страницах: каждая подключает тот же хедер и читает язык из сессии.
5. `header("Location: " . $_SERVER["REQUEST_URI"])` + `exit` — перенаправить на эту же страницу (зачем — ниже).
6. `$_SESSION["lang"] ?? "ru"` — язык из сессии, а при первом заходе (в сессии пусто) — русский.
7. `$t = $texts[$lang]` — все тексты на выбранном языке.
8. `basename($_SERVER["SCRIPT_NAME"], ".php")` — имя текущей страницы: `sights`. По нему хедер выбирает `<title>` и выделяет пункт меню.

### Зачем перенаправление после POST (PRG)

Если после обработки формы просто показать страницу, браузер запомнит, что она получена **POST-запросом**. Тогда при обновлении (F5) он спросит «Отправить форму повторно?».

Поэтому используется приём **PRG** — Post / Redirect / Get:

1. **Post** — браузер отправил форму;
2. **Redirect** — сервер обработал её и ответил `Location: sights.php`;
3. **Get** — браузер сам открыл страницу обычным GET-запросом.

Теперь F5 просто перезагружает страницу.

### Форма и меню в хедере

```php
<select name="lang" onchange="this.form.submit()">
    <?php foreach ($languages as $code => $name): ?>
        <option value="<?= $code ?>" <?= $code === $lang ? "selected" : "" ?>><?= $name ?></option>
    <?php endforeach; ?>
</select>
```

Пункты списка не написаны вручную, а генерируются циклом из `$languages` — альтернативный синтаксис `foreach (): ... endforeach;` из ЛР7. Тернарный оператор ставит `selected` у текущего языка.

```php
<nav>
    <?php foreach ($t["nav"] as $file => $title): ?>
        <a href="<?= $file ?>.php" class="<?= $file === $page ? "active" : "" ?>"><?= $title ?></a>
    <?php endforeach; ?>
</nav>
```

**Перекрёстные ссылки** — с каждой страницы можно перейти на каждую. Меню стоит в хедере, значит, оно есть на всех страницах. Ключи массива `nav` совпадают с именами файлов, поэтому ссылка строится как `<?= $file ?>.php` → `sights.php`. Текущая страница получает класс `active` и выделяется жирным.

### Путь данных целиком

| Шаг | Что происходит | Где |
|---|---|---|
| 1 | Пользователь выбрал «Беларуская» на `sights.php` | браузер |
| 2 | `onchange` → браузер отправляет `POST sights.php`, в теле `lang=be` | браузер → сервер |
| 3 | Проверка прошла → `$_SESSION["lang"] = "be"` → `Location: sights.php` | `header.php` |
| 4 | Браузер делает `GET sights.php` и прикладывает куку `PHPSESSID` | браузер → сервер |
| 5 | `session_start()` находит сессию → `$lang = "be"` → `$t = $texts["be"]` | `header.php` |
| 6 | Страница выводится по-белорусски | браузер |
| 7 | Клик «Кухня» → `GET food.php` → тот же хедер → та же сессия → снова `"be"` | `header.php` |

Шаг 7 — это и есть «текст **на всех страницах** отображается на выбранном языке».

## Поля HTML-форм — общая справка к заданиям 4, 6, 7

В заданиях 4, 6 и 7 используется много разных полей. Все они — тег `<input>` с разным атрибутом `type` (кроме `select` и `textarea`).

Главное правило: **на сервер уходит только поле, у которого есть `name`**. Что придёт в PHP — `$_GET["name"]` или `$_POST["name"]` — зависит от `method` формы.

| Поле | Как выглядит | Что придёт в PHP |
|---|---|---|
| `<input type="text">` | строка ввода | то, что ввели: `"Влад"` |
| `<input type="password">` | строка, символы скрыты точками | то, что ввели — **открытым текстом**, точки только на экране |
| `<input type="email">` | строка; браузер проверяет, что есть `@` | `"v@example.com"` |
| `<input type="tel">` | строка для телефона; на телефоне открывается цифровая клавиатура | `"+375291234567"` — браузер формат **не** проверяет |
| `<input type="number">` | число со стрелками; `min`, `max` | `"19"` — **строка** |
| `<input type="date">` | календарь | `"2006-03-01"` — всегда в формате ГГГГ-ММ-ДД |
| `<input type="time">` | выбор времени | `"07:30"` |
| `<input type="range">` | ползунок; `min`, `max` | `"5"` |
| `<input type="color">` | выбор цвета | `"#f5c542"` |
| `<input type="radio">` | кружок, выбрать **один** из группы | `value` выбранного |
| `<input type="checkbox">` | галочка | `value` (по умолчанию `"on"`), если отмечена; **ничего**, если нет |
| `<select>` + `<option>` | выпадающий список | `value` выбранного `option` |
| `<textarea>` | многострочный текст | то, что ввели |
| `<input type="hidden">` | **не видно** на странице | его `value` |
| `<button type="submit">` | кнопка «отправить форму» | `value` кнопки, если у неё есть `name` |

Четыре особенности, которые важны в лабе:

**1. Все значения приходят строками.** Даже из `number` и `range` приходит `"19"`, а не `19`. Нужно число — приводим: `(int) $_POST["age"]` (ЛР2).

**2. Radio — одна группа по общему `name`.** Кружки с одинаковым `name` связаны: можно выбрать только один, и на сервер уйдёт `value` выбранного.

**3. Неотмеченный checkbox не отправляется вообще.** Ключа в `$_POST` просто нет. Поэтому проверка галочки — `isset($_POST["agree"])`, а не сравнение с `true`.

**4. `name="x[]"` — несколько значений в массив.** Если у нескольких полей имя заканчивается на `[]`, PHP собирает их значения в массив:

```html
<input type="checkbox" name="breakfast[]" value="каша">
<input type="checkbox" name="breakfast[]" value="сырники">
```

```php
// отметили обе галочки
$_POST["breakfast"];  // ["каша", "сырники"]
```

Без `[]` каждое следующее значение затирало бы предыдущее, и пришло бы только последнее.

Полезные атрибуты полей:

| Атрибут | Что делает |
|---|---|
| `required` | браузер не даст отправить форму с пустым полем |
| `value="..."` | значение по умолчанию (у `checkbox` и `radio` — что уйдёт на сервер) |
| `checked` | у `radio` / `checkbox` — отмечен при открытии страницы |
| `placeholder="..."` | серая подсказка внутри пустого поля |
| `min`, `max` | границы для `number`, `range`, `date` |

`required`, `type="email"` и `min`/`max` проверяются **только в браузере**. Их легко обойти — отключить в DevTools или отправить запрос вручную. Поэтому всё важное проверяется ещё раз на сервере, в PHP.

### Одна страница — три состояния

Всё задание — один файл `task4.php`. Что он покажет, зависит от того, что уже известно:

| Что известно                            | Что показать                               |
| --------------------------------------- | ------------------------------------------ |
| в `$_SESSION["user"]` есть пользователь | «С возвращением, {логин}!»                 |
| в адресе есть имя — шаг 1 уже пройден   | шаг 2: логин, пароль, галочка              |

В коде это переменная `$view` и цепочка `if / elseif / else` в альтернативном синтаксисе (ЛР7), которая выбирает, какой кусок HTML вывести.

### Шаг 1 — форма методом GET

```html
<form method="get" action="task4.php">
    <input type="text" name="name" required>
    <input type="date" name="birth" required>
    <input type="tel" name="phone" required>
    <input type="email" name="email" required>
    <button type="submit">Далее</button>
</form>
```

При отправке браузер собирает поля в адрес:

```
task4.php?name=Влад&birth=2006-03-01&phone=%2B375291234567&email=v%40example.com
```

`%2B` и `%40` — так в адресе кодируются `+` и `@` (URL-кодирование). PHP раскодирует их сам, в `$_GET["phone"]` будет `"+375291234567"`.

Страница открывается заново, видит в `$_GET` имя и показывает шаг 2.

### `trim($строка)` — убрать пробелы по краям

```php
trim("  Влад \n");  // "Влад"
```

Из ЛР5: убирает пробелы, табуляции и переводы строк в начале и конце. Здесь — чтобы имя из одних пробелов считалось пустым.

### Как данные шага 1 доживают до конца — скрытые поля

Шаг 2 отправляется **новым** запросом методом POST. В нём будут только поля формы шага 2. Имя, телефон и прочее из шага 1 потерялись бы — сервер ничего не помнит (см. «Основу»).

Поэтому на шаге 2 данные шага 1 кладутся в форму **скрытыми полями**:

```html
<input type="hidden" name="name" value="Влад">
<input type="hidden" name="birth" value="2006-03-01">
<input type="hidden" name="phone" value="+375291234567">
<input type="hidden" name="email" value="v@example.com">
```

`type="hidden"` — поле, которого не видно на странице, но которое уходит на сервер вместе с остальными. Так при отправке шага 2 в `$_POST` окажутся и логин с паролем, и всё из шага 1.

Скрытое поле видно в DevTools и его можно изменить. Для имени и телефона это не страшно, но секретные данные так передавать нельзя — их хранят в сессии.

### `htmlspecialchars($текст)` — безопасный вывод

```php
htmlspecialchars('<script>alert("x")</script>');
// &lt;script&gt;alert(&quot;x&quot;)&lt;/script&gt;
```

Была в ЛР5: заменяет `<`, `>`, `&`, `"`, `'` на HTML-сущности. Браузер показывает их как обычные символы, а не выполняет как код.

Здесь это вопрос **безопасности**. Имя приходит от пользователя и выводится на страницу. Если ввести в поле имени `<script>…</script>` и вывести как есть, браузер выполнит этот код — это атака **XSS** (межсайтовый скриптинг). Поэтому всё, что ввёл пользователь, перед выводом проходит через `htmlspecialchars`.

В `task4.php` для краткости объявлена маленькая функция:

```php
function e(string $text): string
{
    return htmlspecialchars($text);
}
```

и вывод выглядит так: `<?= e($name) ?>`.

### Шаг 2 — форма методом POST

```html
<form method="post" action="task4.php">
    <!-- скрытые поля шага 1 -->
    <input type="text" name="login" required>
    <input type="password" name="password" required>
    <input type="checkbox" name="agree" id="agree">
    <label for="agree">Я согласен с правилами сайта</label>
    <button type="submit">Зарегистрироваться</button>
</form>
```

- `type="password"` прячет символы только **на экране**. На сервер пароль уходит обычным текстом, поэтому формы с паролями отправляют методом POST, чтобы пароль не попал в адресную строку и историю браузера.
- `<label for="agree">` — подпись, связанная с полем по `id`: клик по тексту ставит галочку.

### Проверка на сервере и массив ошибок

```php
if ($_SERVER["REQUEST_METHOD"] === "POST" && isset($_POST["login"])) {
    $login = trim($_POST["login"]);
    $password = $_POST["password"] ?? "";
    $agree = isset($_POST["agree"]);

    if ($login === "") {
        $errors[] = "Введите логин";
    }
    if (strlen($password) < 6) {
        $errors[] = "Пароль должен быть не короче 6 символов";
    }
    if (!$agree) {
        $errors[] = "Нужно согласиться с правилами сайта";
    }
    ...
}
```

- `isset($_POST["agree"])` — галочка стоит, если ключ вообще пришёл (неотмеченный checkbox не отправляется).
- Ошибки собираются в массив `$errors` — приём из ЛР7 (проверка пароля). Если массив пустой — регистрация успешна. Если нет — снова показывается шаг 2 со списком ошибок, а введённый логин подставляется обратно в поле.

Галочка согласия по условию «может поставить» — я понял это так: поставить её можно, но без неё регистрация **не проходит**, как на настоящих сайтах. На странице в этом случае будет ошибка «Нужно согласиться с правилами сайта».

### `password_hash($пароль, $алгоритм)` — хеш пароля

```php
$hash = password_hash("secret1", PASSWORD_DEFAULT);
// $2y$10$WdwK6k8mAxuv.mtragNkNu49Nx/8S7TWskm4EeCITmmhO1nY0A5vm
```

Превращает пароль в **хеш** — длинную строку, из которой исходный пароль получить обратно **нельзя**. `PASSWORD_DEFAULT` — использовать алгоритм, который PHP считает надёжным сейчас (bcrypt; хеш начинается с `$2y$`).

У одного и того же пароля хеш каждый раз **разный** — в него подмешивается случайная «соль». Поэтому два одинаковых пароля в базе не выдают друг друга.

Пароли никогда не хранят открытым текстом — ни в сессии, ни в базе. Если хранилище утечёт, злоумышленник получит только хеши.

### `password_verify($пароль, $хеш)` — проверить пароль

```php
password_verify("secret1", $hash);  // true
password_verify("Secret1", $hash);  // false
```

Пара к `password_hash`: проверяет, подходит ли введённый пароль к сохранённому хешу. Сравнивать хеши через `===` нельзя — из-за соли они всегда разные. В этой лабе не используется (входа по паролю нет), но с `password_hash` её стоит знать в паре.

### Успешная регистрация

```php
$_SESSION["user"] = [
    "name" => $_POST["name"],
    "birth" => $_POST["birth"],
    "phone" => $_POST["phone"],
    "email" => $_POST["email"],
    "login" => $login,
    "password" => password_hash($password, PASSWORD_DEFAULT),
];
session_regenerate_id(true);
header("Location: task4.php");
exit;
```

1. Все данные — массивом в `$_SESSION["user"]`.
2. `session_regenerate_id(true)` — после «входа» меняем id сессии (защита от фиксации сессии, задание 2).
3. `header("Location")` + `exit` — перенаправление, приём PRG из задания 3: после F5 форма не отправится повторно.

После перенаправления страница видит `$_SESSION["user"]` и показывает «С возвращением, {логин}!». И так при каждом следующем открытии, пока жива сессия.

Чтобы пройти регистрацию заново, есть кнопка «Выйти»: она отправляет POST с `logout`, и сервер выполняет `unset($_SESSION["user"])` — удаляет из сессии только этот ключ.

### `print_r($значение, true)` — получить вывод строкой

```php
$text = print_r([1], true);  // "Array\n(\n    [0] => 1\n)\n"
```

`print_r` (ЛР6) обычно сразу печатает. Если вторым аргументом передать `true`, она **возвращает** результат строкой и ничего не печатает — так же, как `var_export(..., true)` в ЛР4.

Здесь это нужно, чтобы пропустить весь вывод через `htmlspecialchars` перед показом: `<?= e(print_r($_SESSION["user"], true)) ?>`.

## Задание 5 — `$_SERVER` в куках и в сессии

> Получите данные о вашем сервере, используя суперглобальный массив `$_SERVER`. Запишите в куки и в сессию имя хоста, ip-адрес, протокол, номер порта и имя скрипта. Дополните скрипт сравнением текущих значений с сохранёнными в куки и в сессии. Закройте браузер и откройте его снова. Что произошло? Измените имя скрипта и обновите страницу. Что изменилось?

### Нужные ключи `$_SERVER`

| Что просят | Ключ | Пример в MAMP |
|---|---|---|
| имя хоста | `$_SERVER["SERVER_NAME"]` | `localhost` |
| IP-адрес сервера | `$_SERVER["SERVER_ADDR"]` | `127.0.0.1` или `::1` |
| протокол | `$_SERVER["SERVER_PROTOCOL"]` | `HTTP/1.1` |
| номер порта | `$_SERVER["SERVER_PORT"]` | `8888` (порт MAMP по умолчанию) или `80` |
| имя скрипта | `$_SERVER["SCRIPT_NAME"]` | `/labwork9/task5.php` |

`::1` — это тот же «свой компьютер», только в записи IPv6, а `127.0.0.1` — в IPv4.

Набор ключей зависит от сервера. Apache в MAMP заполняет все пять, а, например, встроенный сервер PHP не заполняет `SERVER_ADDR`. Поэтому в коде у каждого стоит `?? "нет данных"`: если ключа нет, страница не упадёт.

### Порядок: сначала прочитать, потом записать

```php
// 1. текущие значения
$current = [
    "host" => $_SERVER["SERVER_NAME"] ?? "нет данных",
    ...
];

// 2. что сохранили в прошлый раз
foreach ($current as $key => $value) {
    $fromCookie[$key] = $_COOKIE["server_" . $key] ?? null;
}
$fromSession = $_SESSION["server"] ?? [];

// 3. перезаписать текущими
foreach ($current as $key => $value) {
    setcookie("server_" . $key, $value, time() + 60 * 60 * 24);
}
$_SESSION["server"] = $current;
```

Если сначала записать, а потом сравнивать, сравнение всегда показывало бы «совпадает» — мы сравнивали бы значения сами с собой. Поэтому старые значения сначала копируются в `$fromCookie` и `$fromSession`, и только потом перезаписываются.

Куки ставятся по одной на каждый параметр: `server_host`, `server_ip`, … В одной куке хранится одна строка.

`time() + 60 * 60 * 24` — сутки вперёд: 60 секунд × 60 минут × 24 часа.

### Сравнение

```php
function compare(?string $saved, string $now): string
{
    if ($saved === null) {
        return "<td class='empty'>нет</td>";
    }
    $class = $saved === $now ? "same" : "diff";
    ...
}
```

- `?string` — тип «строка **или** `null`»: сохранённого значения может не быть.
- Нет сохранённого → «нет».
- Совпадает с текущим → зелёная ячейка «✓ совпадает», не совпадает → красная «✗ отличается».

### Первое открытие

В обоих столбцах — «нет». Сессия только что создана, и в ней пусто. Куки поставлены в этом же ответе, а `$_COOKIE` отстаёт на один запрос (задание 1, «Нюанс»). После обновления страницы всё совпадает.

### Ответ на вопрос: закрыли и открыли браузер — что произошло

| Столбец | Что видно             | Почему                                                                                                                                        |
| ------- | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| куки    | значения **на месте** | куки `server_*` поставлены со сроком на сутки — браузер хранит их на диске                                                                    |
| сессия  | **«нет»**             | кука `PHPSESSID` без срока — **сессионная**, браузер удаляет её при закрытии. Без неё сервер не находит старую сессию и создаёт новую, пустую |

Сами данные старой сессии на сервере при этом ещё лежат, пока их не удалит сборщик мусора (`session.gc_maxlifetime`, 24 минуты). Но получить их уже нельзя — номерок потерян.

Важно для эксперимента: браузер нужно закрыть **полностью** (`Cmd + Q` на Mac), а не только окно. И если в Chrome включено «Продолжить работу с того же места», он **восстанавливает** сессионные куки после перезапуска — тогда сессия сохранится. Для чистого эксперимента эту настройку нужно выключить или открыть страницу в окне инкогнито.

### Ответ на вопрос: переименовали скрипт — что изменилось

Переименуй `task5.php`, например, в `task5_renamed.php` и открой по новому адресу. В строке «имя скрипта»:

- «сейчас» — `/labwork9/task5_renamed.php`;
- в куке и в сессии — старое `/labwork9/task5.php` → **«✗ отличается»**.

Остальные параметры совпадают: сервер, порт и протокол те же.

Куки при этом **видны** новой странице. Почему — см. блок про путь куки ниже. После обновления страницы новое имя запишется и снова будет «совпадает». После эксперимента не забудь вернуть файлу имя `task5.php`, иначе ссылка в `lab9.php` перестанет работать.

### Путь куки по умолчанию

У `setcookie` в этом задании не указан путь (4-й аргумент). Тогда браузер берёт **папку страницы**, которая поставила куку: для `/labwork9/task5.php` это `/labwork9/`. Кука будет отправляться на все страницы в этой папке — поэтому переименованный файл в той же папке её видит. В другой папке (например, `/labwork8/`) этих кук не будет.

У `PHPSESSID` путь `/` — весь сайт. Поэтому одна сессия общая для всех лабораторных.

### Проверка идентификатора

```php
if ($_SERVER["REQUEST_METHOD"] === "POST" && ($_POST["survey_id"] ?? "") === SURVEY_ID) {
```

Ответ сохраняется, только если пришёл **наш** идентификатор. Без проверки, подменив скрытое поле в DevTools на `survey_id=user`, можно было бы записать мусор в `$_SESSION["user"]` и сломать регистрацию из задания 4. Скрытое поле — тоже данные от пользователя, им нельзя верить.

### Ответ — массив, приведение типов

```php
$answer = [
    "name" => trim($_POST["name"] ?? ""),
    "age" => (int) ($_POST["age"] ?? 0),
    "breakfast" => $_POST["breakfast"] ?? [],
    ...
];
```

- `?? ""` / `?? []` — значение по умолчанию, если поле не пришло. Особенно важно для checkbox: если ни одной галочки нет, ключа `breakfast` в `$_POST` нет совсем.
- `(int)` — `number` и `range` приходят строками, а возраст и настроение — числа.

### Нумерация с 1

```php
$results = $_SESSION[SURVEY_ID] ?? [];
$nextNumber = count($results) === 0 ? 1 : max(array_keys($results)) + 1;
$results[$nextNumber] = $answer;
$_SESSION[SURVEY_ID] = $results;
```

Если просто написать `$results[] = $answer`, первый ответ получит ключ `0` (ЛР2: автонумерация с нуля). А в примере из задания ключи начинаются с `1`.

Поэтому номер считается вручную:

- ответов нет → `1`;
- есть → самый большой номер + 1. `array_keys($results)` (ЛР6) — все номера, `max` — наибольший.

Именно «наибольший + 1», а не «количество + 1». Если удалить ответ № 1 из двух, останется один ответ с номером 2. «Количество + 1» дало бы снова 2 и затёрло бы существующий ответ. «Наибольший + 1» даёт 3.

После сохранения — перенаправление на `task6.php?saved=3` (PRG). Номер в адресе нужен, чтобы показать «Ответ № 3 сохранён».

### Вторая страница — таблица и кнопки «Удалить»

```php
<?php foreach ($results as $number => $answer): ?>
    <tr>
        <td><?= $number ?></td>
        <td><?= htmlspecialchars($answer["name"]) ?></td>
        ...
        <td>
            <form method="post">
                <button type="submit" name="delete" value="<?= $number ?>">Удалить</button>
            </form>
        </td>
    </tr>
<?php endforeach; ?>
```

У каждой строки — своя маленькая форма с одной кнопкой. У кнопки есть `name="delete"` и `value` с номером ответа. При нажатии на сервер уходит `delete=2` — так сервер узнаёт, какую строку удалить.

Удаление — POST, а не ссылка с GET: оно меняет данные (см. GET и POST в задании 3).

`implode(", ", $answer["breakfast"])` (ЛР5) склеивает массив завтраков в строку. `?: "—"` — если строка пустая, вывести прочерк.

Цвет показан цветным квадратиком: значение `#f5c542` подставляется прямо в CSS — `style="background: #f5c542"`.

### `unset($массив[$ключ])` — удалить элемент массива

```php
$number = (int) $_POST["delete"];
unset($_SESSION[SURVEY_ID][$number]);
```

`unset` (ЛР8) удаляет переменную или **один элемент массива** вместе с ключом. Остальные элементы и их номера не меняются: удалили № 1 — остался № 2, перенумерации нет.

Удаление из `$_SESSION` — это и есть «удаляет из сессии». После перенаправления страница перечитывает сессию, и строки там уже нет — это «очищает ответы со страницы».

## Задание 7 — фильтр книг через GET

> Для передачи данных используйте метод GET.
>
> Создайте форму для фильтрации данных (например, книг или фильмов), используя как минимум 4 различных типа полей (например, checkbox, radio, select, text), в форме также должна быть кнопка поиска (submit). При нажатии на кнопку должна открываться другая страница, а в `$_GET` – сохраняться информация о выбранных параметрах. На другой странице выведите в красивом виде эту информацию.

### Форма — 5 типов полей

```html
<form method="get" action="task7_results.php">
    <input type="text" name="query">
    <select name="genre">...</select>
    <input type="radio" name="format" value="бумажная">
    <input type="checkbox" name="lang[]" value="русский">
    <input type="number" name="year_from">
    <button type="submit">Найти</button>
</form>
```

- `action="task7_results.php"` — форма отправляется на **другую** страницу.
- `method="get"` — параметры попадают в адрес:

```
task7_results.php?query=&genre=фэнтези&format=&lang[]=русский&year_from=
```

Поэтому для поиска и фильтров используют именно GET: результат можно добавить в закладки или отправить ссылкой — по ней откроется тот же поиск.

Пустые поля тоже отправляются — с пустым значением (`query=`). Не отправляются только неотмеченные checkbox и radio.

### Чтение параметров

```php
$query = trim($_GET["query"] ?? "");
$genre = $_GET["genre"] ?? "";
$format = $_GET["format"] ?? "";
$langs = (array) ($_GET["lang"] ?? []);
$yearFrom = (int) ($_GET["year_from"] ?? 0);
```

`(array)` — приведение к массиву. Языки должны прийти массивом (`lang[]`), но адрес можно написать руками: `?lang=abc`. Тогда пришла бы строка, и `implode` упал бы с ошибкой. `(array) "abc"` превращает строку в массив `["abc"]`, а настоящий массив оставляет как есть.

### `mb_stripos($где_ищем, $что_ищем)` — поиск без учёта регистра

```php
mb_stripos("Властелин колец Дж. Р. Р. Толкин", "толкин");  // 26 — позиция найдена
mb_stripos("Дюна", "толкин");                             // false
```

Как `strpos` (ЛР5), но:

- `i` в названии — **без учёта регистра**: «Толкин» и «толкин» совпадают;
- `mb_` — работает с символами, а не байтами.

Возвращает позицию первого вхождения или `false`. Как и у `strpos`, проверять нужно строго: `=== false` (совпадение в самом начале даёт `0`).

Без `mb_` не сработает: `stripos("Толкин", "толкин")` вернёт `false` — однобайтовая версия умеет менять регистр только у латиницы (ЛР5, «Основа»).

### `in_array($что_ищем, $массив)` — есть ли значение в массиве

```php
in_array("русский", ["русский", "английский"]);  // true
in_array("белорусский", ["русский"]);           // false
```

Возвращает `true`, если такое **значение** есть в массиве. Отличие от `array_key_exists` (задание 3): та ищет среди ключей, а `in_array` — среди значений.

Сравнение нестрогое: `in_array("5", [5])` → `true`. Строгое — третьим аргументом: `in_array("5", [5], true)` → `false`.

### Фильтрация — `array_filter` с замыканием

```php
$found = array_filter($books, function ($book) use ($query, $genre, $format, $langs, $yearFrom) {
    if ($query !== "" && mb_stripos($book["title"] . " " . $book["author"], $query) === false) {
        return false;
    }
    if ($genre !== "" && $book["genre"] !== $genre) {
        return false;
    }
    if ($format !== "" && $book["format"] !== $format) {
        return false;
    }
    if (count($langs) > 0 && !in_array($book["lang"], $langs)) {
        return false;
    }
    if ($yearFrom > 0 && $book["year"] < $yearFrom) {
        return false;
    }
    return true;
});
```

`array_filter` (ЛР6) оставляет книги, для которых функция вернула `true`. Функция — замыкание, параметры фильтра попадают в неё через `use` (ЛР8).

Логика каждой проверки одинаковая: «если параметр **выбран** и книга ему **не подходит** — выбросить». Пустой параметр («любой», не отмечено) не отсеивает ничего. Книга проходит, только если не провалила ни одной проверки — то есть подходит под **все** выбранные параметры сразу.

### Красивый вывод параметров

```php
$chosen = [
    "Название или автор" => $query,
    "Жанр" => $genre,
    "Формат" => $format,
    "Язык" => implode(", ", $langs),
    "Изданы не раньше" => $yearFrom > 0 ? "$yearFrom года" : "",
];
```

Параметры собраны в массив «подпись → значение» и выводятся циклом в карточку-таблицу. Пустое значение показывается серым «не важно» — понятнее, чем пустая клетка.

Ниже на странице — для наглядности:

- **строка запроса** из адреса — `$_SERVER["QUERY_STRING"]`, всё после `?`;
- **найденные книги**;
- **содержимое `$_GET`** через `print_r` — видно, что `lang` пришёл массивом.

### `urldecode($строка)` — раскодировать адрес

```php
urldecode("lang%5B%5D=%D1%80%D1%83%D1%81");  // "lang[]=рус"
```

В адресе русские буквы и спецсимволы хранятся закодированными: `%D1%80` — это байты буквы «р» (кириллица — 2 байта, ЛР5). `urldecode` превращает их обратно в читаемый текст. В `$_GET` PHP раскодирует значения сам, а `$_SERVER["QUERY_STRING"]` — это строка «как есть», поэтому для показа её раскодируем вручную.

## Что могут спросить на защите

### 1. Чем сессия отличается от куки?

Кука хранится в браузере и содержит сами данные. Сессия хранит данные на сервере, а в браузере — только куку с идентификатором. Поэтому в сессии безопасно хранить то, что пользователь не должен менять (например, кто вошёл в аккаунт), а в куках — только несекретные настройки.

### 2. Где хранятся данные сессии?

По умолчанию — в файлах во временной папке сервера, по одному файлу на сессию: `sess_<id>`. Папка задаётся настройкой `session.save_path`.

### 3. Когда сессия заканчивается?

- когда вызвали `session_destroy()`;
- когда закрыли браузер: кука `PHPSESSID` по умолчанию без срока и удаляется при закрытии браузера, а без куки сервер сессию не найдёт;
- когда сессия долго не использовалась: PHP периодически удаляет старые файлы. Время задаёт настройка `session.gc_maxlifetime`, по умолчанию 1440 секунд — 24 минуты.

### 4. Почему `session_start()` должен стоять в начале файла?

Он отправляет куку, а куки отправляются в заголовках ответа. Заголовки уходят раньше тела, и после первого выведенного символа добавить их нельзя.

### 5. Почему после `session_destroy()` кука осталась?

`session_destroy()` удаляет только данные на сервере и браузеру ничего не отправляет. Чтобы удалить куку, нужно отдельно вызвать `setcookie()` с тем же именем и сроком в прошлом.

### 6. Зачем нужен `session_regenerate_id()`?

Сменить id открытой сессии, сохранив данные. Защищает от фиксации сессии — его вызывают после входа в аккаунт.

### 7. Почему язык передаётся через POST, а не GET?

Так требует задание, и так правильно: форма меняет состояние (настройку в сессии), а для изменений используют POST. GET — для получения данных и ссылок, которые можно сохранить или отправить.

### 8. Что будет, если отключить куки в браузере?

Браузер не будет присылать `PHPSESSID`, и каждый запрос откроет новую пустую сессию. Язык «забудется» при каждом переходе.

### 9. Зачем в задании 4 скрытые поля на шаге 2?

Шаг 2 — новый запрос, сервер не помнит данных шага 1. Скрытые поля (`type="hidden"`) везут имя, дату рождения, телефон и e-mail в форме шага 2, и при отправке они приходят в `$_POST` вместе с логином и паролем.

### 10. Почему пароль хранится хешем, а не как есть?

Хеш нельзя превратить обратно в пароль. Если данные утекут, злоумышленник не узнает пароли. Проверка пароля при входе — `password_verify`.

### 11. Зачем `htmlspecialchars` при выводе введённых данных?

Чтобы введённый пользователем HTML или JavaScript показался как текст, а не выполнился. Иначе возможна атака XSS.

### 12. Что произошло после перезапуска браузера в задании 5?

Куки `server_*` со сроком на сутки сохранились. Сессионная кука `PHPSESSID` (без срока) удалилась, поэтому сервер не нашёл старую сессию — в столбце «сессия» пусто.

### 13. Что изменилось после переименования скрипта?

В строке «имя скрипта» текущее значение (новое имя) не совпало с сохранёнными в куке и сессии (старое имя). Остальные параметры совпали.

### 14. Почему результаты опроса нумеруются с 1, и что будет после удаления?

Номер считается как «наибольший номер + 1» (для пустого массива — 1). После удаления номера не перенумеровываются, а новый ответ получает следующий свободный номер — ничего не затирается.

### 15. Почему фильтр в задании 7 через GET?

Поиск ничего не меняет на сервере, только читает данные. Параметры в адресе позволяют сохранить поиск в закладки или отправить ссылкой.
