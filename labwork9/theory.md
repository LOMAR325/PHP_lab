## 0. Основа

### HTTP не помнит пользователя

Браузер и сервер общаются **запросами**: браузер просит страницу → сервер отвечает → соединение закрыто. Следующий запрос сервер обрабатывает «с чистого листа». Он не знает, что это тот же человек, что секунду назад выбрал язык или вошёл в аккаунт.

Каждый запуск PHP-скрипта — тоже с нуля: все переменные, созданные в прошлый раз, исчезли.

Чтобы «помнить» пользователя между запросами, есть два механизма: **куки** и **сессии**.

### Заголовки и тело ответа

Ответ сервера состоит из двух частей:

1. **Заголовки** (headers) — служебная информация: тип содержимого, куки, перенаправления.
2. **Тело** — сам HTML, который видно на странице.

Заголовки всегда идут **первыми**. Как только PHP вывел хоть один символ тела (`echo`, HTML-текст, даже пробел или пустая строка перед `<?php`), заголовки уже отправлены, и добавить к ним ничего нельзя.

Поэтому всё, что работает с заголовками, — `session_start()`, `setcookie()`, `header()` — должно стоять **в самом начале файла, до любого вывода**. Иначе — предупреждение `Headers already sent` / `Session cannot be started after headers have already been sent`.

Именно поэтому в каждом файле лабы работа с сессией вынесена в блок `<?php ... ?>` перед `<html>`.

### Куки (cookies)

**Кука** — маленький кусочек текста «имя = значение», который сервер просит браузер сохранить. Дальше браузер **сам** прикладывает его к каждому запросу на этот сайт.

```
сервер → браузер:  Set-Cookie: PHPSESSID=ggpf1lg574jd3n3r80junou873; path=/
браузер → сервер:  Cookie: PHPSESSID=ggpf1lg574jd3n3r80junou873
```

- Хранится **у пользователя**, в браузере → пользователь может её посмотреть, удалить или подделать.
- Маленький объём (около 4 КБ).
- Имеет срок жизни. Если срок не задан — живёт до закрытия браузера.

В PHP:
- поставить куку — `setcookie("имя", "значение", время_истечения)`;
- прочитать — `$_COOKIE["имя"]`;
- удалить — `setcookie("имя", "", time() - 3600)`: срок в прошлом, браузер сам её удалит.

### Сессия

**Сессия** — хранилище данных о пользователе **на сервере**. Работает так:

1. `session_start()` — PHP придумывает случайный **идентификатор** сессии (например, `ggpf1lg574jd3n3r80junou873`) и создаёт на сервере файл для данных.
2. Идентификатор отправляется браузеру **в куке** с именем `PHPSESSID`.
3. В скрипте данные кладутся в массив `$_SESSION` — как в обычный массив.
4. При следующем запросе браузер присылает куку `PHPSESSID`, `session_start()` по ней находит **тот же файл** и заполняет `$_SESSION` сохранёнными данными.

Аналогия: гардероб. Пальто (данные) висит в гардеробе (на сервере), а у тебя на руках только номерок (кука с id). По номерку тебе отдают именно твоё пальто.

| | Куки | Сессия |
|---|---|---|
| где хранятся данные | в браузере | на сервере |
| что лежит в браузере | все данные | только id сессии |
| может ли пользователь подделать | да | данные — нет, только id |
| объём | ~4 КБ | ограничен только сервером |
| как обратиться в PHP | `$_COOKIE` | `$_SESSION` (после `session_start()`) |

`session_start()` нужно вызывать **на каждой странице**, где используется `$_SESSION`. Без него `$_SESSION` пуст, даже если сессия существует.

## Задание 1 — куки до, во время и после сессии

### Где в браузере найти куки

**Chrome:** правый клик по странице → «Просмотреть код» (или `Cmd + Option + I` на Mac, `F12` на Windows) → вкладка **Application** (если её не видно — она прячется за `>>`) → в левом меню раздел **Storage → Cookies** → адрес сайта (`http://localhost:...`).

Справа появится таблица кук этого сайта:

| Столбец | Что значит |
|---|---|
| Name | имя куки — `PHPSESSID` |
| Value | значение — id сессии |
| Domain, Path | для какого сайта и какой части сайта кука: `localhost`, `/` — для всего сайта |
| Expires / Max-Age | когда истекает; `Session` — до закрытия браузера |
| Size | размер в байтах |
| HttpOnly, Secure, SameSite | настройки безопасности куки |

Если кликнуть по строке, внизу будет её полное значение. Таблица обновляется сама, перезагружать DevTools не нужно.

Там же куку можно удалить вручную: правый клик по строке → Delete.

### Скриншоты

Лежат в `labwork9/screenshots/`, `lab9.php` находит их через `glob("screenshots/*.png")` и выводит по порядку, подписывая именем файла. На каждом слева — `cookies.php`, справа — DevTools → Application → Cookies.

1. **До открытия сессии** — таблица кук пустая, `$_COOKIE` пустой.
2. **После «Открыть сессию»** — в таблице появилась `PHPSESSID`, её значение совпадает с id, который вывел PHP. При этом `$_COOKIE` на странице ещё пустой (почему — ниже, в «Нюанс»).
3. **После «Завершить сессию (только session_destroy)»** — кука **осталась** с тем же значением.
4. **После «Завершить сессию и удалить куку»** — таблица снова пустая.

### Почему куки изменились

```php
if ($action === "start") {
    session_start();
    $_SESSION["opened_at"] = date("H:i:s");
}
```

- **До** `session_start()` сервер ничего не просил сохранить — кук нет.
- `session_start()` создаёт сессию и отправляет заголовок `Set-Cookie: PHPSESSID=<id>; path=/`. Браузер сохраняет куку — она появляется в DevTools. Теперь браузер будет присылать её с каждым запросом, и по ней сервер узнаёт «свою» сессию.

### Почему после `session_destroy()` кука осталась

```php
} elseif ($action === "destroy") {
    session_start();
    $_SESSION = [];
    session_destroy();
}
```

`session_destroy()` удаляет **только данные на сервере** (файл сессии). Про куку в браузере он ничего не знает и ничего браузеру не отправляет. Кука с уже недействительным id остаётся. При следующем `session_start()` PHP увидит, что файла с таким id нет, и создаст новую пустую сессию.

Зачем нужен `session_start()` перед `session_destroy()`: уничтожить можно только **открытую** сессию. Сначала её надо «найти» по куке.

`$_SESSION = []` — очищает массив в текущем скрипте. `session_destroy()` удаляет файл на сервере, но уже заполненный `$_SESSION` до конца работы скрипта остался бы.

### Как удалить и куку

```php
} elseif ($action === "delete_cookie") {
    session_start();
    $_SESSION = [];
    $params = session_get_cookie_params();
    setcookie(session_name(), "", time() - 3600, $params["path"], $params["domain"], $params["secure"], $params["httponly"]);
    session_destroy();
}
```

Это стандартный способ из документации PHP.

- `session_name()` — имя куки (`PHPSESSID`);
- `""` — пустое значение;
- `time() - 3600` — срок истёк час назад → браузер удаляет куку;
- `session_get_cookie_params()` — путь, домен и прочие параметры, с которыми куку ставили. Удалить куку можно, только указав **те же** путь и домен, иначе браузер посчитает её другой кукой.

Сервер отправляет: `Set-Cookie: PHPSESSID=deleted; expires=Thu, 01 Jan 1970 ...; Max-Age=0; path=/`.

### Нюанс: `$_COOKIE` отстаёт на один запрос

На странице выводится `print_r($_COOKIE)`. Сразу после «Открыть сессию» там **пусто**, хотя в DevTools кука уже есть. Почему:

`$_COOKIE` — это куки, которые браузер прислал **в этом** запросе. А кука `PHPSESSID` появилась только в **ответе** на него. Браузер пришлёт её со следующего запроса — поэтому есть ссылка «Обновить без действий»: после неё кука видна в `$_COOKIE`.

Так же с удалением: на странице «удалить куку» `$_COOKIE` ещё показывает старую куку — браузер прислал её до того, как получил команду удалить.

## Задание 2 — имя, идентификатор и данные сессии

### Почему отдельные страницы, а не `lab9.php`

`session_start()` должен стоять до вывода, а значит — в самом начале файла. Если поставить его в `lab9.php`, сессия открывалась бы при каждом заходе на лабу, и в задании 1 не получилось бы увидеть «куки до сессии». Поэтому задание 2 — на своих страницах `session_write.php` и `session_read.php`.

### Имя и идентификатор

```php
session_start();

$oldName = session_name();  // PHPSESSID
$oldId = session_id();      // jislmv0jbgcp91kaet2qsu2s3d
```

- `session_name()` без аргумента — **имя** сессии, оно же имя куки. По умолчанию `PHPSESSID`.
- `session_id()` без аргумента — **идентификатор** текущей сессии: случайная строка, номерок из гардероба.

### Попытка изменить

```php
$renameResult = @session_name("MYSESSION");
$changeIdResult = @session_id("vlad123");
```

С аргументом эти функции **устанавливают** новое значение. Но только **до** `session_start()`. Когда сессия уже открыта, PHP отказывается: выдаёт предупреждение (`Session name cannot be changed when a session is active`) и возвращает `false`. На странице видно `false` и что имя/id остались прежними.

`@` перед вызовом — **оператор подавления ошибок**: предупреждение не выводится на страницу. Здесь он нужен не для того, чтобы спрятать проблему, а потому что вывод предупреждения — это вывод, после него `session_regenerate_id()` уже не смог бы отправить новую куку (заголовки ушли бы). Результат проверяется через возвращённое `false`.

Как изменить **правильно**:

| Что | Как | Когда |
|---|---|---|
| имя | `session_name("MYSESSION")` | **до** `session_start()`, и так на **каждой** странице — иначе другие страницы будут искать куку `PHPSESSID` и не найдут сессию |
| id | `session_id("abc")` | **до** `session_start()` — откроется (или создастся) сессия с этим id |
| id открытой сессии | `session_regenerate_id(true)` | после `session_start()` |

### `session_regenerate_id(true)`

```php
session_regenerate_id(true);
$newId = session_id();
```

Создаёт **новый** id для текущей сессии, переносит в неё все данные и отправляет браузеру новую куку. `true` — удалить старый файл сессии.

Зачем это нужно в реальной жизни: защита от **фиксации сессии**. Злоумышленник может подсунуть жертве ссылку с заранее известным id. Если после входа в аккаунт id сменить, известный злоумышленнику id станет бесполезным. Поэтому `session_regenerate_id(true)` вызывают сразу после успешного входа.

### Запись в сессию

```php
$_SESSION["time"] = date("d.m.Y H:i:s");
$_SESSION["name"] = "Влад";
$_SESSION["age"] = 20;
$_SESSION["subjects"] = [
    "Высокоуровневые языки программирования",
    "Веб-дизайн",
    ...
];
```

`$_SESSION` — суперглобальный массив (ЛР8), работает как обычный ассоциативный массив. В него можно положить строки, числа и даже **массивы** — PHP сам их сохранит в файл (сериализует) и восстановит при следующем `session_start()`.

Специально ничего «сохранять» не нужно: PHP записывает `$_SESSION` в файл автоматически, когда скрипт заканчивается.

### Чтение на другой странице

```php
session_start();

if (isset($_SESSION["name"])) {
    echo "имя: {$_SESSION["name"]}\n";
    foreach ($_SESSION["subjects"] as $i => $subject) {
        echo "  ", $i + 1, ". $subject\n";
    }
} else {
    echo "в сессии нет данных — сначала откройте session_write.php\n";
}
```

1. `session_start()` — браузер прислал куку `PHPSESSID`, PHP нашёл по ней файл и заполнил `$_SESSION`.
2. `isset(...)` — проверка: если на `session_read.php` зайти первым (или после удаления куки в задании 1), данных нет, и без проверки было бы `Undefined array key`.
3. `{$_SESSION["name"]}` — фигурные скобки нужны, чтобы вставить элемент массива со строковым ключом внутрь строки в двойных кавычках (ЛР4).

Время на второй странице совпадает со временем записи, а не текущим: это доказывает, что значение пришло из сессии, а не посчиталось заново.

## Задание 3 — сайт с выбором языка

### Устройство

```
site/
├── lang.php     ← все тексты: $languages и $texts
├── header.php   ← session_start, обработка POST, <head>, меню, форма с select
├── footer.php   ← подвал, закрывающие </body></html>
├── index.php    ← страницы: require header → свой текст → require footer
├── sights.php
└── food.php
```

Каждая страница выглядит так:

```php
<?php require "header.php"; ?>

<h1><?= $t["pages"]["sights"]["title"] ?></h1>
...
<?php require "footer.php"; ?>
```

`require "header.php"` — **первая строка** страницы, до любого HTML. Это важно: внутри хедера стоит `session_start()` и `header("Location: ...")`, им нужно, чтобы вывода ещё не было.

`<?= ... ?>` — короткая запись `<?php echo ... ?>` (ЛР7).

### Тексты — `lang.php`

```php
$languages = [
    "ru" => "Русский",
    "be" => "Беларуская",
    "en" => "English",
];

$texts = [
    "ru" => [
        "choose" => "Язык:",
        "nav" => ["index" => "Главная", "sights" => "Достопримечательности", "food" => "Кухня"],
        "pages" => [
            "index" => ["title" => "О городе", "text" => [...]],
            ...
        ],
    ],
    "be" => [...],
    "en" => [...],
];
```

Многомерный массив (ЛР5): первый ключ — язык, дальше одинаковая структура для всех языков. Тогда выбор языка — это одна строка:

```php
$t = $texts[$lang];   // все тексты на нужном языке
```

и дальше везде `$t["nav"]["index"]`, `$t["pages"]["food"]["title"]` — код страниц от языка не зависит.

Чтобы добавить новый язык, достаточно дописать его в `$languages` и `$texts` — ни одну страницу менять не надо.

### Форма с `select`

```php
<form method="post">
    <label>
        <?= $t["choose"] ?>
        <select name="lang" onchange="this.form.submit()">
            <?php foreach ($languages as $code => $name): ?>
                <option value="<?= $code ?>" <?= $code === $lang ? "selected" : "" ?>><?= $name ?></option>
            <?php endforeach; ?>
        </select>
    </label>
</form>
```

- `method="post"` — данные уходят методом **POST** (по условию задания).
- `<select name="lang">` — выпадающий список. На сервер уйдёт пара `lang = <value выбранного option>`, например `lang=be`.
- Пункты списка генерируются циклом из `$languages` — альтернативный синтаксис `foreach (): ... endforeach;` из ЛР7.
- `selected` — у пункта текущего языка, чтобы в списке был выбран именно он.
- `onchange="this.form.submit()"` — «при изменении языка форма должна отправляться». Это маленький кусочек JavaScript: когда пользователь выбрал пункт, браузер сам отправляет форму. Без него пришлось бы добавлять кнопку «Отправить».
- `action` у формы не указан → форма отправляется **на ту же страницу**, на которой находится. Поэтому язык можно менять на любой странице, и пользователь на ней же остаётся.

### GET и POST

Оба — способы отправить данные на сервер.

| | GET | POST |
|---|---|---|
| где данные | в адресной строке: `page.php?lang=be` | в теле запроса, в адресе их не видно |
| в PHP | `$_GET["lang"]` | `$_POST["lang"]` |
| объём | ограничен длиной адреса | большой |
| можно сохранить в закладки / отправить ссылкой | да | нет |
| для чего | получить данные: поиск, фильтры, номер страницы | изменить что-то на сервере: формы входа, регистрации, настройки |

В задании 1 используется GET (`cookies.php?action=start`) — это просто ссылки. В задании 3 — POST, потому что форма меняет настройку пользователя.

### Обработка — начало `header.php`

```php
session_start();
require_once "lang.php";

if ($_SERVER["REQUEST_METHOD"] === "POST" && isset($_POST["lang"]) && array_key_exists($_POST["lang"], $languages)) {
    $_SESSION["lang"] = $_POST["lang"];
    header("Location: " . $_SERVER["REQUEST_URI"]);
    exit;
}

$lang = $_SESSION["lang"] ?? "ru";
$t = $texts[$lang];
$page = basename($_SERVER["SCRIPT_NAME"], ".php");
```

По строкам:

1. `session_start()` — открыть сессию, в ней может уже лежать выбранный язык.
2. `$_SERVER["REQUEST_METHOD"] === "POST"` — страницу открыли отправкой формы, а не обычным переходом. `$_SERVER` — суперглобальный массив с информацией о запросе.
3. `isset($_POST["lang"])` — в форме действительно был язык.
4. `array_key_exists($_POST["lang"], $languages)` — **проверка**: такой язык у нас есть. Данные от пользователя нельзя принимать на веру: через DevTools можно отправить `lang=abc`. Без проверки дальше было бы `$texts["abc"]` → ошибки на всех страницах.
5. `$_SESSION["lang"] = ...` — запомнить язык в сессии. Именно поэтому он сохраняется при переходе на **другие** страницы: каждая страница подключает тот же хедер и читает язык из сессии.
6. `header("Location: ...")` + `exit` — **перенаправление** на эту же страницу, только уже обычным GET-запросом. Это приём **PRG** (Post/Redirect/Get). Без него после выбора языка обновление страницы (F5) показывало бы окно «Отправить форму повторно?». `exit` — остановить скрипт: после перенаправления ничего выводить не нужно.
7. `$_SESSION["lang"] ?? "ru"` — язык из сессии, а если его там нет (первый заход) — русский по умолчанию. Оператор `??` из ЛР8.
8. `basename($_SERVER["SCRIPT_NAME"], ".php")` — имя текущей страницы без пути и расширения: `/labwork9/site/sights.php` → `sights`. Нужно, чтобы хедер знал, какой `<title>` вывести и какой пункт меню выделить.

### Перекрёстные ссылки

```php
<nav>
    <?php foreach ($t["nav"] as $file => $title): ?>
        <a href="<?= $file ?>.php" class="<?= $file === $page ? "active" : "" ?>"><?= $title ?></a>
    <?php endforeach; ?>
</nav>
```

Меню в хедере, значит оно есть на **каждой** странице, и с любой страницы можно перейти на любую. Ключи массива `nav` совпадают с именами файлов, поэтому ссылки строятся циклом. Текущая страница выделяется классом `active`.

### Путь данных целиком

```
1. Пользователь выбрал «Беларуская» на sights.php
2. onchange → браузер отправляет POST sights.php, тело: lang=be
3. header.php: проверка → $_SESSION["lang"] = "be" → Location: sights.php
4. Браузер делает GET sights.php (с кукой PHPSESSID)
5. header.php: session_start() → $_SESSION["lang"] = "be" → $t = $texts["be"]
6. Страница выводится по-белорусски
7. Клик «Кухня» → GET food.php → тот же хедер → тот же $_SESSION["lang"] = "be"
```

## Вопросы, которые могут задать на защите

### 1. Чем сессия отличается от куки?

Кука хранится в браузере и содержит сами данные. Сессия хранит данные на сервере, а в браузере — только куку с идентификатором. Поэтому в сессии безопасно хранить то, что пользователь не должен менять (например, id вошедшего пользователя), а в куках — только несекретные настройки.

### 2. Где хранятся данные сессии?

По умолчанию — в файлах во временной папке сервера (путь в настройке `session.save_path`), по одному файлу на сессию: `sess_<id>`. Можно настроить хранение в базе данных или Redis.

### 3. Когда сессия заканчивается?

- когда вызвали `session_destroy()`;
- когда браузер закрыли — кука `PHPSESSID` по умолчанию без срока и удаляется при закрытии браузера, а без куки сервер сессию не найдёт;
- когда сессия долго не использовалась — PHP периодически удаляет старые файлы (настройка `session.gc_maxlifetime`, по умолчанию 1440 секунд = 24 минуты).

### 4. Почему `session_start()` должен стоять в начале?

Он отправляет куку, а куки отправляются в заголовках ответа. Заголовки уходят до тела, и после первого выведенного символа добавить их нельзя.

### 5. Зачем нужен `session_regenerate_id()`?

Сменить id открытой сессии, сохранив данные. Защищает от фиксации сессии — вызывается после входа в аккаунт.

### 6. Почему язык выбирается через POST, а не GET?

Так требует задание, и так правильно: форма меняет состояние (настройку в сессии), а для изменений используют POST. GET — для получения данных и ссылок, которые можно сохранить.

### 7. Что будет, если отключить куки в браузере?

Браузер не будет присылать `PHPSESSID`, и каждый запрос будет открывать новую пустую сессию. Язык «забудется» при каждом переходе.
