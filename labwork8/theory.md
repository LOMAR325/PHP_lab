## 0. Основа

### Функция

Функция — именованный кусок кода, который можно вызывать много раз:

```php
function greet(string $name): string
{
    return "Привет, $name!";
}

echo greet("Влад");  // Привет, Влад!
```

- `greet` — имя функции;
- `string $name` — **параметр**: переменная, в которую попадёт переданное значение. `string` перед ним — тип;
- `: string` — тип возвращаемого значения;
- `return` — что функция отдаёт обратно в место вызова;
- `"Влад"` при вызове — **аргумент**: конкретное значение для параметра.

### Передача по значению — по умолчанию

Обычно функция получает **копию** значения. Что бы функция ни делала со своим параметром, исходная переменная снаружи не изменится:

```php
function addOne(int $x) { $x++; }

$n = 5;
addOne($n);
echo $n;  // 5 — изменилась копия внутри функции, а не $n
```

### Ссылка `&`

**Ссылка** — второе имя для **той же самой** переменной. Не копия, а именно тот же «ящик» в памяти под другим названием.

```php
$a = 5;
$b = &$a;   // $b — другое имя для $a
$b = 10;
echo $a;    // 10 — меняли $b, но это тот же ящик
```

Аналогия: у человека есть имя и прозвище. Если позвать по прозвищу и дать ему что-то в руки — это получит тот же человек.

Значок `&` встречается в четырёх местах, и везде значит «не копия, а ссылка»:

| Где | Пример | Смысл |
|---|---|---|
| присваивание | `$b = &$a;` | `$b` — второе имя для `$a` |
| параметр функции | `function f(&$x)` | функция меняет переменную, которую ей передали |
| `use` в замыкании | `use (&$email)` | замыкание меняет внешнюю переменную |
| перед именем функции | `function &f()` | функция возвращает ссылку, а не копию |

Разорвать ссылку — `unset($b)`. Удаляется только имя `$b`, значение остаётся у `$a`.

### Область видимости

**Область видимости** (scope) — где переменная «видна», то есть где к ней можно обратиться.

- Переменные, созданные **вне** функций, — **глобальные**.
- Переменные, созданные **внутри** функции, — **локальные**: они существуют только пока функция работает, и снаружи их не видно.

Главная особенность PHP: функция **не видит** глобальные переменные. Внутри функции — своя отдельная «комната»:

```php
$x = 10;

function show() {
    echo $x;  // Warning: Undefined variable $x
}
```

Как пробить эту стену — `global`, `$GLOBALS`, `use` — разобрано в задании 3.

## Задание 1 — что выведется и почему

### # 1 — `44`

```php
$a = 5;
$b =& $a;
echo $b = 4, $a;
```

1. `$b =& $a` — то же, что `$b = &$a`: `$b` становится ссылкой на `$a`.
2. `echo` с запятыми выводит выражения по очереди слева направо.
3. Первое выражение — `$b = 4`. Присваивание само по себе возвращает значение — `4` (это было в ЛР3, задание 1 # 2). Печатается **4**. Но `$b` — это `$a`, поэтому теперь и `$a = 4`.
4. Второе выражение — `$a`, а он уже 4. Печатается **4**.

Результат: **`44`**.

### # 2 — `86`

```php
$a = 4;
$b = 6;
$arr = [&$a, &$a];
$arr[0] = 8;
echo $a, $b;
```

`[&$a, &$a]` — массив, **оба** элемента которого — ссылки на `$a`. То есть `$arr[0]`, `$arr[1]` и `$a` — три имени одной переменной.

`$arr[0] = 8` → `$a` теперь 8.

`$b` ни с чем не связана, остаётся 6.

Результат: **`86`**.

В лабе между примерами стоит `unset($a, $b)`. Все примеры лежат в одном файле, и без `unset` ссылка `$b → $a` из # 1 «дожила» бы до # 2. Тогда `$b = 6` изменило бы и `$a`, и результат стал бы `88`. Наглядная иллюстрация того, что ссылка живёт, пока её явно не разорвут.

### # 3.1 — `23`

```php
$a = 2;
$make = fn() => ++$a;
$a2 = $make();
echo $a, $a2;
```

`fn() => ...` — стрелочная функция (ЛР6). Она **видит внешние переменные сама**, но получает их **по значению** — как копию на момент создания.

1. Стрелочная функция захватила копию `$a` = 2.
2. При вызове `++$a` увеличивает **копию** до 3 и возвращает 3. `$a2 = 3`.
3. Внешняя `$a` не изменилась — 2.

Результат: **`23`**.

### # 3.2 — `33`

```php
$a = 2;
$make = fn(&$a) => ++$a;
$a2 = $make($a);
echo $a, $a2;
```

Теперь `$a` — **параметр, принимаемый по ссылке** (`&$a`). Внутри функции параметр называется так же, но это ссылка на переданную переменную.

1. `$make($a)` — передаём внешнюю `$a` по ссылке.
2. `++$a` увеличивает **саму внешнюю** `$a` до 3 и возвращает 3.

Результат: **`33`**.

Сравнение # 3.1 и # 3.2 — суть темы: без `&` функция работает с копией, с `&` — с оригиналом.

### # 4 — `Меня где-то вызвали`, затем Fatal error

```php
echo show();
echo show2();

function show() {
    echo "Меня где-то вызвали";
}

$a = true;

if ($a) {
    function show2() {
        echo "Меня тоже где-то вызвали?";
    }
}
```

Здесь две особенности.

**1. Обычную функцию можно вызвать до её объявления.** Перед выполнением PHP сначала читает весь файл целиком и заранее регистрирует все функции, объявленные «на верхнем уровне». Поэтому `show()` в первой строке работает, хотя написана ниже. Это называется **поднятие** (hoisting).

**2. Функция внутри `if` объявляется только тогда, когда выполнение дойдёт до этого `if`.** Такая функция называется **условной**. Заранее её PHP не регистрирует — он не знает, выполнится ли условие.

По шагам:

1. `echo show()` — функция печатает `Меня где-то вызвали`. Она ничего не возвращает (`return` нет), значит возвращает `null`, и `echo null` не печатает ничего.
2. `echo show2()` — до `if` выполнение ещё не дошло, функции `show2` пока не существует → **Fatal error: Call to undefined function show2()**. Скрипт останавливается.

Результат: `Меня где-то вызвали`, затем фатальная ошибка.

Как и в ЛР7, пример вынесен в отдельный файл и показан в рамке, чтобы ошибка не оборвала всю страницу.

Если бы вызов `show2()` стоял **после** блока `if`, всё бы работало.

## Задание 2 — три функции и «функции переменных»

### Неограниченное количество аргументов — `...`

```php
function sumNumbers(int|float ...$numbers): int|float
{
    return array_sum($numbers);
}

sumNumbers(1, 2.5, 3, 10);  // 16.5
sumNumbers();               // 0
```

`...$numbers` — **variadic-параметр** («переменное число аргументов»). Сколько бы аргументов ни передали, все они собираются в **массив** `$numbers`. Дальше с ним работаем как с обычным массивом — `array_sum` (ЛР6) считает сумму.

Variadic-параметр должен быть **последним** в списке параметров.

### Типизация: только числа

`int|float` — **объединённый тип** (union type): «целое **или** дробное». Применяется к каждому аргументу.

Но есть нюанс. По умолчанию PHP **нестрогий**: если передать строку `"2"`, он молча превратит её в число 2. Чтобы запретить это, в **самом начале** файла стоит:

```php
<?php declare(strict_types=1); ?>
```

Это включает **строгий режим типов**: теперь `"2"` — это строка, а не число, и передача её в `int|float` вызывает ошибку `TypeError`.

В лабе это проверено через `try/catch` (ЛР4): вызов `sumNumbers(1, "2")` выбрасывает `TypeError`, а `catch` её ловит и выводит сообщение вместо падения страницы.

`declare(strict_types=1)` обязан быть **самой первой** командой файла — даже раньше `<html>`. Поэтому `lab8.php` начинается со строки `<?php declare(strict_types=1); ?>`.

### Рекурсия

**Рекурсивная** функция — функция, которая вызывает **саму себя**.

```php
function countElements(array $array): int
{
    $count = 0;
    foreach ($array as $element) {
        if (is_array($element)) {
            $count += countElements($element);
        } else {
            $count++;
        }
    }
    return $count;
}
```

Идея: перебираем элементы.

- Обычное значение — считаем как 1.
- Вложенный массив — мы не знаем, сколько там внутри и насколько глубоко. Но у нас уже есть функция, которая умеет считать элементы массива, — это **она сама**. Вызываем её для вложенного массива и прибавляем результат.

Разберём `[1, [2, 3, [4, [5, 6]]], 7, [[8]]]`:

```
countElements([1, [2,3,[4,[5,6]]], 7, [[8]]])
├─ 1                        → 1
├─ [2, 3, [4, [5, 6]]]      → countElements(...)
│   ├─ 2                    → 1
│   ├─ 3                    → 1
│   └─ [4, [5, 6]]          → countElements(...)
│       ├─ 4                → 1
│       └─ [5, 6]           → countElements(...) = 2
│                             итого 1 + 2 = 3
│     итого 1 + 1 + 3 = 5
├─ 7                        → 1
└─ [[8]]                    → countElements(...) → countElements([8]) = 1
итого 1 + 5 + 1 + 1 = 8
```

Результат: **8**. Для сравнения, обычный `count()` вернёт 4 — он считает только верхний уровень.

Почему рекурсия не бесконечная: каждый вызов получает массив **глубже** предыдущего. Рано или поздно попадётся массив без вложенных массивов — там функция больше не вызывает себя и просто возвращает число. Такой случай называется **базовым случаем** рекурсии.

### Количество аргументов — `func_num_args()`

```php
function showArgsCount(): void
{
    echo "передано аргументов: ", func_num_args(), "\n";
}

showArgsCount();               // 0
showArgsCount("a", "b", "c");  // 3
```

Особенность PHP: функции можно передать **больше** аргументов, чем у неё объявлено параметров. Ошибки не будет — лишние просто не попадут в переменные. Но функция может их узнать:

- `func_num_args()` — сколько аргументов передали;
- `func_get_args()` — массив всех переданных аргументов.

У `showArgsCount` вообще нет параметров, но передать ей можно сколько угодно.

### Функции переменных

```php
$sumFunc = "sumNumbers";
$sumFunc(1, 2.5, 3, 10);  // то же, что sumNumbers(1, 2.5, 3, 10)
```

Если в переменной лежит **строка с именем функции**, а после переменной поставить круглые скобки, PHP вызовет функцию с этим именем.

Зачем: так можно выбирать, какую функцию вызвать, **во время работы программы**. Например, имя функции приходит из настроек или выбирается условием.

## Задание 3 — три способа достать глобальную переменную

Переменная `$email` создана снаружи, на верхнем уровне файла, — она глобальная. Как мы помним, функция её не видит. Задание — три разных способа это обойти.

### `use` — для замыкания

```php
$add_local_part = function (string $name) use (&$email): void {
    $email .= $name;
};

$add_local_part("student");
```

**Замыкание** (closure) — анонимная функция (без имени), сохранённая в переменную. Подробно — в ответах на вопросы.

`use (...)` — список внешних переменных, которые замыкание «забирает с собой» внутрь.

`&` в `use (&$email)` здесь **обязателен**. Без него `use` передаёт **копию**: замыкание дописало бы имя к своей копии, а настоящий `$email` остался бы пустым.

Поскольку это не обычная функция, а переменная, она вызывается через переменную: `$add_local_part(...)`.

### `global` — объявить, что переменная глобальная

```php
function add_at(): void
{
    global $email;
    $email .= "@";
}
```

`global $email;` внутри функции значит: «под именем `$email` здесь имеется в виду глобальная переменная, а не новая локальная». После этой строки `$email` внутри функции — ссылка на глобальную `$email`.

### `$GLOBALS` — массив всех глобальных переменных

```php
function add_domain(string $domain): void
{
    $GLOBALS["email"] .= $domain;
}
```

`$GLOBALS` — **суперглобальный** массив. «Суперглобальный» значит, что он виден **везде** — в любой функции, без `global` и `use`. В нём лежат все глобальные переменные: ключ — имя переменной без `$`, значение — её значение.

`$GLOBALS["email"]` — это и есть глобальная `$email`.

Другие суперглобальные массивы, которые встретятся дальше: `$_GET`, `$_POST` (данные форм), `$_SERVER` (информация о запросе), `$_SESSION`, `$_COOKIE`.

### Итог

```
в начале:          ''
add_local_part():  'student'
add_at():          'student@'
add_domain():      'student@example.com'
```

| Способ     | Где работает                                  | Как записывается                  |
| ---------- | --------------------------------------------- | --------------------------------- |
| `use`      | только в замыканиях (`function () use (...)`) | `use (&$email)`                   |
| `global`   | в обычной функции                             | `global $email;` в начале функции |
| `$GLOBALS` | везде                                         | `$GLOBALS["email"]`               |

На практике все три стараются использовать пореже. Функцию проще понять и проверить, когда всё нужное ей передаётся через параметры, а результат возвращается через `return`.

## Задание 4 — драники: подключение файлов, замыкание, callback

### Подключение файлов

```php
require "ingredients.php";  // $potatoes, $onions, $eggs, $flour, $salt, $oil
require "fridge.php";       // $fridge — массив продуктов
```

`require` вставляет и выполняет код файла в этом месте (ЛР7). Переменные, созданные в подключённом файле, становятся доступны в основном файле — как будто были написаны прямо здесь.

Редактор кода (VS Code) может подчёркивать `$fridge` и `$potatoes` как «Undefined variable». Это ложная тревога: редактор не «заглядывает» в подключённые файлы, а PHP при выполнении их видит.

### Замыкание с `use`

```php
$checkFridge = function () use ($potatoes, $onions, $eggs, $flour, $salt, $oil, $fridge): bool {
    $needed = [
        "картофель" => $potatoes,
        "лук" => $onions,
        ...
    ];

    $enough = true;
    foreach ($needed as $product => $amount) {
        $have = $fridge[$product] ?? 0;
        ...
        if ($have < $amount) {
            $enough = false;
        }
    }
    return $enough;
};
```

1. Через `use` замыкание забирает внутрь все ингредиенты и холодильник. Здесь `&` **не нужен**: мы только читаем значения, ничего не меняем.
2. Отдельные переменные-ингредиенты собираются в массив `$needed` с теми же названиями, что в холодильнике. Так их удобно сравнить в одном цикле.
3. Для каждого продукта: сколько нужно (`$amount`) и сколько есть (`$have`).
4. `$fridge[$product] ?? 0` — оператор `??` («null-слияние»): если такого продукта в холодильнике нет вообще, взять 0. Без `??` при отсутствующем ключе было бы предупреждение `Undefined array key`.
5. `$enough` — флаг (ЛР7, задание 6): изначально `true`, а если хоть одного продукта не хватает — `false`.

### Callback и `call_user_func`

**Callback** («обратный вызов») — функция, которую не вызывают напрямую по имени, а передают куда-то как значение, чтобы её вызвали там. Мы уже передавали callback-функции в `array_filter` и `array_map` (ЛР6).

```php
function cookDraniki(int $potatoes, int $eggs): void { ... }

call_user_func("cookDraniki", $potatoes, $eggs);
```

`call_user_func(функция, аргумент1, аргумент2, ...)` — вызвать функцию, переданную первым аргументом, с остальными аргументами. Функцию можно передать:

- строкой с именем — `"cookDraniki"`;
- переменной с замыканием — `call_user_func($checkFridge)`.

Результат такой же, как у прямого вызова `cookDraniki($potatoes, $eggs)`. Смысл `call_user_func` — в случаях, когда **какую** функцию вызывать, становится известно только во время работы программы.

Есть и `call_user_func_array(функция, массив_аргументов)` — то же, но аргументы передаются массивом.

## Задание 5 — генератор, меняющий массив по ссылке

### Генератор и `yield`

**Генератор** — функция, которая отдаёт значения **по одному**, по мере запроса, а не все сразу.

```php
function addExclamation(array &$array): Generator
{
    foreach ($array as &$item) {
        $item .= "!";
        yield $item;
    }
}
```

Генератором функцию делает слово **`yield`** («отдать»). `yield` похож на `return`, но:

- `return` возвращает значение и **завершает** функцию;
- `yield` отдаёт значение и **ставит функцию на паузу**. При следующем запросе функция продолжит ровно с места паузы — со всеми своими переменными.

Возвращаемый тип — `Generator`.

### Генератор ленивый

Главное, что видно в выводе лабы:

```php
$generator = addExclamation($words);
print_r($words);  // ещё без восклицательных знаков!
```

Вызов `addExclamation($words)` **не выполняет** код функции. Он только создаёт объект-генератор — «заготовку», готовую выполняться. Код начнёт работать, когда генератор начнут **перебирать**:

```php
foreach ($generator as $word) {
    echo "генератор выдал: $word\n";
}
```

На каждой итерации `foreach` генератор «просыпается», выполняется до следующего `yield`, отдаёт значение в `$word` и снова засыпает:

| Итерация `foreach` | Что делает генератор                              | `$word`                 |
| ------------------ | ------------------------------------------------- | ----------------------- |
| 1                  | `"привет"` → `"привет!"`, yield                   | `привет!`               |
| 2                  | `"пока"` → `"пока!"`, yield                       | `пока!`                 |
| 3                  | `"ура"` → `"ура!"`, yield                         | `ура!`                  |
| —                  | цикл в генераторе закончился → генератор завершён | `foreach` заканчивается |

Такое поведение — «ничего не делать, пока не попросят» — называется **ленивыми вычислениями**.

### Две ссылки

Чтобы генератор менял **исходный** массив `$words`, ссылки нужны в двух местах:

1. `array &$array` — параметр по ссылке: `$array` внутри — это сам `$words`, а не копия.
2. `foreach ($array as &$item)` — перебор по ссылке: `$item` на каждой итерации — это сам элемент массива, а не его копия. `$item .= "!"` меняет элемент прямо в массиве.

Если убрать любую из двух `&`, `$words` после перебора останется без восклицательных знаков.

## Задание 6 — талон к специалисту

```php
function printTicket(int &$queue, string $specialist = "Иванов И. И., терапевт"): void
{
    static $ticketNumber = 0;
    $ticketNumber++;
    ...
    $queue = max(0, $queue - rand(1, 3));
}
```

Здесь сразу три механизма.

### Статическая переменная — номер талона

Обычная локальная переменная создаётся заново при каждом вызове функции и исчезает, когда функция заканчивается.

**Статическая** переменная (`static`) создаётся **один раз** — при первом вызове. Её значение **сохраняется между вызовами**:

| Вызов | `$ticketNumber` до `++` | после |
|---|---|---|
| 1-й | 0 (инициализация `= 0` выполнилась) | 1 |
| 2-й | 1 (инициализация пропущена, значение осталось) | 2 |
| 3-й | 2 | 3 |

Без `static` каждый талон был бы № 1.

При этом статическая переменная остаётся **локальной**: снаружи функции её не видно и случайно испортить нельзя. В этом её преимущество перед глобальным счётчиком.

### Параметр по ссылке — очередь

`int &$queue` — функция получает не копию числа, а саму внешнюю переменную `$queue`. Поэтому строка

```php
$queue = max(0, $queue - rand(1, 3));
```

уменьшает очередь **снаружи**. Это видно в выводе: «очередь до» — 12, «очередь после» — меньше.

- `rand(1, 3)` — случайно уменьшаем на 1–3 человека;
- `max(0, ...)` — очередь не может стать отрицательной: из двух чисел берётся большее, а 0 больше любого отрицательного.

### Параметр по умолчанию — специалист

`string $specialist = "Иванов И. И., терапевт"` — у параметра есть **значение по умолчанию**. Если аргумент не передали, берётся оно:

```php
printTicket($queue);                               // Иванов И. И., терапевт
printTicket($queue, "Петрова А. С., стоматолог");  // Петрова А. С., стоматолог
```

Параметры со значением по умолчанию должны стоять **после** обязательных.

### Дата и время

`date("d.m.Y H:i:s")` — текущие дата и время по шаблону: `d` — день, `m` — месяц, `Y` — год, `H` — часы, `i` — минуты, `s` — секунды.

`date_default_timezone_set("Europe/Minsk")` — какой часовой пояс использовать (UTC+3). Без этой строки PHP мог бы взять пояс из настроек сервера, например UTC, и время на талоне отставало бы на 3 часа.

## Задание 7 — возврат по ссылке

```php
function &getChanging(): int
{
    static $changing = 0;
    return $changing;
}
```

`&` **перед именем функции** значит: функция возвращает не копию значения, а **ссылку** на переменную.

Но чтобы получить именно ссылку, `&` нужен **и при вызове**:

```php
$copy = getChanging();       // без & — получили копию, хоть функция и умеет отдавать ссылку
$copy = 50;
getChanging();               // 0 — копия ни на что не влияет

$changing = &getChanging();  // с & — получили ссылку на статическую $changing
$changing = 100;
getChanging();               // 100 — изменили статическую переменную снаружи функции
```

Почему переменная обязательно **статическая**. Обычная локальная переменная исчезает, когда функция заканчивается. Ссылка на неё указывала бы «в никуда». Статическая живёт всё время работы скрипта, поэтому ссылку на неё можно спокойно держать снаружи.

Это нарушение изоляции: статическая переменная задумана как скрытая внутри функции, а возврат по ссылке открывает к ней доступ снаружи. Задание показывает, что так **можно**, но в реальном коде так делают редко.

## Ответы на контрольные вопросы

### 1. Что такое замыкания? Для чего используется ключевое слово `use`?

**Замыкание** (closure) — анонимная функция (функция без имени), которую можно сохранить в переменную, передать в другую функцию как аргумент или вернуть из функции.

```php
$greet = function (string $name) {
    return "Привет, $name";
};
echo $greet("Влад");
```

В PHP замыкание — это объект класса `Closure`.

Замыкание, как и любая функция, **не видит** переменные снаружи. Ключевое слово **`use`** перечисляет внешние переменные, которые замыкание должно «захватить» и видеть внутри:

```php
$greeting = "Привет";
$greet = function (string $name) use ($greeting) {
    return "$greeting, $name";
};
```

- `use ($x)` — захват **по значению**: замыкание получает копию `$x` на момент **создания** замыкания. Если потом изменить `$x` снаружи, замыкание этого не заметит.
- `use (&$x)` — захват **по ссылке**: замыкание работает с самой переменной и может её менять (задание 3).

Стрелочные функции `fn() => ...` захватывают внешние переменные автоматически, без `use`, но только по значению (задание 1 # 3.1).

Применение: callback для `array_map`, `array_filter`, `usort`; обработчики событий; функции, «помнящие» данные из места своего создания (задание 4).

### 2. Какую область видимости имеют функции? Как получить значение глобальной переменной изнутри функции? Из другого файла?

**Сами функции** (объявленные через `function имя()`) имеют **глобальную** область видимости: объявленную функцию можно вызвать из любого места программы — из другой функции, из подключённого файла. Функции на верхнем уровне файла доступны даже до строки объявления (задание 1 # 4).

**Переменные внутри функции** имеют **локальную** область видимости: функция не видит внешние переменные, а её переменные не видны снаружи.

Получить глобальную переменную внутри функции можно тремя способами (задание 3):

- `global $x;` — объявить внутри функции, что `$x` — глобальная;
- `$GLOBALS["x"]` — суперглобальный массив, виден везде;
- `use ($x)` — для замыканий.

Лучший способ — вообще не обращаться к глобальным переменным, а **передать значение параметром**.

**Из другого файла**: подключить его через `require`/`include` (задание 4). Код подключённого файла выполняется так, будто написан в месте подключения. Если подключение стоит на верхнем уровне, все его переменные становятся глобальными переменными основного файла. Если подключить файл **внутри функции**, его переменные станут локальными переменными этой функции.

### 3. Что такое функция-генератор? Где могут использоваться ленивые вычисления?

**Функция-генератор** — функция с `yield`, которая отдаёт значения по одному и между ними «засыпает», сохраняя своё состояние (задание 5). Вызов генератора не выполняет код, а возвращает объект `Generator`. Код выполняется по частям при переборе через `foreach`.

**Ленивые вычисления** — вычислять значение только тогда, когда оно действительно понадобилось, и не держать в памяти всё сразу.

Где это полезно:

- **Большие файлы.** Читать файл на миллион строк построчно: генератор отдаёт одну строку за раз, и в памяти всегда лежит только одна строка, а не весь файл.
- **Большие выборки из базы данных** — обрабатывать записи по одной, а не загружать в массив сразу все.
- **Бесконечные последовательности** — например, генератор всех чисел Фибоначчи. Массив бесконечной длины создать нельзя, а генератор просто отдаёт следующее число, пока его просят.
- **Дорогие вычисления**, результат которых может не понадобиться: если перебор прервали через `break`, оставшиеся значения так и не будут посчитаны.

| `fn() => ...`                 | стрелочная функция                             | видит внешние переменные сама, по значению |
