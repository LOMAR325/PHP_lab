# Лабораторная работа №13 — теория

Тема: **объектно-ориентированное программирование (ООП)**. До сих пор программа была набором переменных и функций, которые их обрабатывают. В ООП данные и функции, которые с ними работают, собираются вместе — в **объекты**. Так устроены почти все большие программы на PHP: WordPress, Laravel, Joomla.

Все примеры проверены в PHP 8.3 (как в MAMP).

## 0. Основа

### Класс и объект

**Класс** — чертёж. **Объект** — вещь, сделанная по чертежу.

| Жизнь | ООП |
|---|---|
| чертёж автомобиля | класс `Car` |
| конкретная машина во дворе | объект `$myCar` |
| цвет, пробег | **свойства** (поля) — данные объекта |
| ехать, тормозить | **методы** — функции объекта |

По одному чертежу можно сделать сколько угодно машин. У каждой свой цвет и пробег, но устроены они одинаково.

Мы уже встречали объекты: в ЛР2 (задание 9) создавали класс `Point`, а в ЛР11 подключение к базе `$pdo` — тоже объект класса `PDO`.

### Объявить класс, создать объект

```php
class Book
{
    public string $title;            // свойство
    public int $year;                // свойство

    public function info(): string   // метод
    {
        return "{$this->title} ({$this->year})";
    }
}

$book = new Book();          // создать объект — экземпляр класса
$book->title = "Дюна";       // записать свойство
$book->year = 1965;
echo $book->info();          // вызвать метод → "Дюна (1965)"
```

| Запись | Значит |
|---|---|
| `class Book { ... }` | объявить класс. Имена классов пишут с большой буквы |
| `new Book()` | создать новый объект этого класса |
| `$book->title` | свойство **этого** объекта. `->` — «у объекта взять…» |
| `$book->info()` | вызвать метод этого объекта |
| `public string $title` | свойство с типом `string` (типизированное, PHP 7.4+) |

### `$this` — «этот объект»

Внутри метода нужен доступ к свойствам того объекта, у которого метод вызвали. Для этого есть `$this`:

```php
$a = new Book(); $a->title = "Дюна";
$b = new Book(); $b->title = "Хоббит";

$a->info();   // внутри info() $this — это $a → "Дюна ..."
$b->info();   // внутри info() $this — это $b → "Хоббит ..."
```

Метод один на весь класс, а `$this` каждый раз — тот объект, слева от `->`.

### Конструктор `__construct`

Неудобно после `new` заполнять каждое свойство отдельно. **Конструктор** — специальный метод, который PHP вызывает **автоматически** при `new`:

```php
class Book
{
    public string $title;
    public int $year;

    public function __construct(string $title, int $year)
    {
        $this->title = $title;
        $this->year = $year;
    }
}

$book = new Book("Дюна", 1965);   // аргументы new попадают в __construct
```

Имя строго `__construct` — **два** подчёркивания в начале. С одним это просто обычный метод, и PHP его сам не вызовет (это одна из ошибок задания 1).

**Короткая запись (PHP 8):** если параметр конструктора объявить с модификатором, PHP сам создаст свойство и запишет в него значение:

```php
class Book
{
    public function __construct(
        private string $title,
        private int $year,
    ) {}
}
```

Это то же самое, что код выше, только короче. Называется «продвижение свойств конструктора» (constructor promotion).

### Модификаторы доступа: `public`, `protected`, `private`

Кому разрешено обращаться к свойству или методу:

| Модификатор | Внутри класса | В классах-наследниках | Снаружи (`$obj->...`) |
|---|---|---|---|
| `public` | ✓ | ✓ | ✓ |
| `protected` | ✓ | ✓ | ✗ |
| `private` | ✓ | ✗ | ✗ |

```php
class Account
{
    private int $balance = 0;
}

$acc = new Account();
echo $acc->balance;   // Error: Cannot access private property Account::$balance
```

Зачем запрещать: снаружи нельзя случайно (или нарочно) написать `$acc->balance = 1000000`. Изменить баланс можно только методами класса, которые проверят, что всё правильно. Это **инкапсуляция** — первый принцип ООП (задание 2).

### Геттеры и сеттеры

Если свойство `private`, а прочитать или изменить его снаружи всё-таки нужно — пишут методы-посредники:

```php
class Book
{
    private int $year;

    public function getYear(): int        // геттер — «получить»
    {
        return $this->year;
    }

    public function setYear(int $year): void   // сеттер — «установить»
    {
        if ($year < 0) {
            throw new Exception("Год не может быть отрицательным");
        }
        $this->year = $year;
    }
}
```

Смысл сеттера — **проверка**: в свойство никогда не попадёт неправильное значение. А если не написать сеттер вовсе, свойство станет **только для чтения** снаружи. Это пригодится в задании 3.

### Статические свойства и методы — `static`, `::`, `self::`

Обычное свойство своё у **каждого** объекта: у каждой книги своё название. **Статическое** — одно **на весь класс**, общее для всех объектов.

```php
class Counter
{
    private static int $count = 0;     // одно на весь класс

    public function __construct()
    {
        self::$count++;                // при каждом new — +1
    }

    public static function total(): int
    {
        return self::$count;
    }
}

new Counter(); new Counter(); new Counter();
echo Counter::total();   // 3
```

| Запись | Значит |
|---|---|
| `static` | свойство или метод принадлежит **классу**, а не объекту |
| `Класс::$свойство`, `Класс::метод()` | обращение к статическому снаружи — через **имя класса** и `::` |
| `self::$свойство` | обращение изнутри класса — «этот класс» |

Статическому методу не нужен объект — его вызывают по имени класса. Поэтому внутри статического метода **нет `$this`**: нет объекта, к которому он относится.

Ещё два слова с `::`:

- `parent::` — «класс-родитель» (в наследнике): `parent::__construct(...)`, `parent::$type`;
- `static::` — «класс, у которого метод реально вызвали». Отличается от `self::`, когда наследник переопределил статическое свойство: `self::` всегда смотрит в класс, где написан код, а `static::` — в наследника (проверено).

### Константы класса

```php
class Book
{
    public const MAX_PAGES = 5000;
}
echo Book::MAX_PAGES;   // 5000
```

Как обычные константы (ЛР7), но живут внутри класса. Пишутся без `$`, обращение через `::`. Мы так писали `PDO::FETCH_ASSOC` в ЛР11 — это константа класса `PDO`.

### Наследование — `extends`

Класс может **расширять** другой: получить все его свойства и методы и добавить свои.

```php
class Animal
{
    public function __construct(protected string $name) {}

    public function introduce(): string
    {
        return "Я {$this->name}";
    }
}

class Cat extends Animal               // Cat — наследник Animal
{
    public function purr(): string
    {
        return "{$this->name} мурлычет";   // $name досталось от Animal
    }
}

$cat = new Cat("Васисуалий");
echo $cat->introduce();   // метод родителя: "Я Васисуалий"
echo $cat->purr();        // свой метод
```

- `Animal` — **родитель** (базовый класс), `Cat` — **наследник** (дочерний класс);
- `protected` свойства наследник видит, `private` — нет;
- наследник может **переопределить** метод родителя — написать метод с тем же именем. Тогда для объектов-наследников работает новая версия.

В PHP класс может наследовать **только один** класс. `class C extends A, B` — синтаксическая ошибка (задание 1). Если нужно «добавить умения» из нескольких мест — для этого **трейты** (`trait` + `use` внутри класса).

`$obj instanceof Animal` — проверка «объект этого класса или его наследника?» → `true` / `false`.

### Абстрактный класс и абстрактный метод

Иногда класс задуман **только** как основа для наследников. Создавать его объекты бессмысленно — например, «животное вообще».

```php
abstract class Animal
{
    abstract public function speak(): string;   // нет тела — только «обещание»

    public function introduce(): string          // обычный метод — можно
    {
        return "Я говорю: " . $this->speak();
    }
}

class Cat extends Animal
{
    public function speak(): string               // наследник ОБЯЗАН реализовать
    {
        return "Мяу";
    }
}
```

| Понятие | Правила |
|---|---|
| `abstract class` | нельзя создать объект: `new Animal()` → `Cannot instantiate abstract class` (проверено) |
| `abstract` метод | **без тела** — после скобок сразу `;`, никаких `{ }` |
| абстрактный метод в классе | класс **обязан** быть `abstract` |
| наследник | обязан реализовать все абстрактные методы, иначе он сам должен быть `abstract` |

Абстрактный метод говорит: «у каждого животного **есть** метод `speak`, но как именно оно говорит — решает конкретный наследник».

### Интерфейс — `interface`, `implements`

**Интерфейс** — список методов, которые класс **обещает** иметь. Только «что умеет», без «как»:

```php
interface Digital
{
    public function getFormat(): string;
    public function getSize(): int;
}

class EBook implements Digital
{
    public function getFormat(): string { return "epub"; }
    public function getSize(): int { return 1200; }
}
```

- в интерфейсе — только объявления методов, без тел;
- `implements` — «класс выполняет интерфейс». Он обязан реализовать **все** методы интерфейса;
- класс может реализовывать **несколько** интерфейсов: `implements Digital, Printable`. Наследовать — только один класс.

Чем интерфейс отличается от абстрактного класса:

| | Абстрактный класс | Интерфейс |
|---|---|---|
| обычные методы с телом | можно | нет |
| свойства | можно | нет (только константы) |
| сколько можно подключить | один (`extends`) | сколько угодно (`implements`) |
| смысл | «**является** разновидностью» (кот является животным) | «**умеет**» (книга умеет быть электронной) |

### Исключения — `throw`, `try / catch`

```php
function divide(int $a, int $b): float
{
    if ($b === 0) {
        throw new Exception("Делить на ноль нельзя");
    }
    return $a / $b;
}

try {
    echo divide(10, 0);
} catch (Exception $e) {
    echo "Ошибка: " . $e->getMessage();
}
```

`throw` прерывает выполнение и «бросает» объект-ошибку наружу, пока его не поймает `catch`. Ловили уже `DivisionByZeroError` (ЛР4), `TypeError` (ЛР8), `PDOException` (ЛР11) — всё это объекты-исключения. `Exception` — их общий класс, а свои классы ошибок можно сделать наследованием:

```php
class BookNotAvailableException extends Exception {}
```

Тогда ошибки разных видов ловят разными `catch`. Пригодится в задании 4.

### Пространства имён — `namespace`, `use`

В большом проекте легко получить два класса с одинаковым именем: `Book` в магазине и `Book` в библиотеке. **Пространство имён** — как папка для имён: `Shop\Book` и `Library\Book` — разные классы.

```php
namespace Shop\Products;     // всё ниже — внутри пространства Shop\Products

class Book {}
```

Полное имя класса — `Shop\Products\Book`. Подробно — в задании 6.

## Задание 1 — найти и исправить ошибки

> Определите, почему не выполнятся следующие скрипты. Измените их таким образом, чтобы они выполнялись корректно.

Для каждого скрипта ниже — настоящий текст ошибки (запускал в PHP 8.3), какое правило нарушено и в какую сторону исправлять.

### Скрипт № 1 — абстрактный метод с телом

```php
class NameClass {
    public $name;

    abstract public function getName() {
        print $this->name;
    }
}
```

```
Fatal error: Abstract function NameClass::getName() cannot contain body
```

**Что нарушено.** Абстрактный метод — это «обещание без реализации», у него **не может быть тела** `{ ... }`. Здесь две ошибки сразу:

1. у абстрактного метода есть тело;
2. абстрактный метод стоит в **не**абстрактном классе. Если убрать только тело, PHP выдаст следующую ошибку: `Class NameClass contains 1 abstract method and must therefore be declared abstract` (проверено).

**Куда исправлять** — два пути, выбери по смыслу:

- метод **должен** работать прямо в этом классе → убрать слово `abstract` у метода;
- метод **должны** реализовать наследники → объявить `abstract class`, у метода убрать тело (`;` после скобок) и сделать класс-наследник, который его реализует.

### Скрипт № 2 — статическое свойство через `->`

```php
class JustClass {
    public static $name = "Просто какой-то класс бебе";
}

$new_class = new JustClass();
echo $new_class->name;
```

```
Notice: Accessing static property JustClass::$name as non static
Warning: Undefined property: JustClass::$name
```

**Что нарушено.** `static`-свойство принадлежит **классу**, а не объекту. `->` ищет свойство **у объекта** — а у объекта такого свойства нет, отсюда «Undefined property». На экран ничего не выводится.

**Куда исправлять.** Обращаться к статическому через `::`: по имени класса `JustClass::$name`. Можно и через объект — `$new_class::$name` (проверено, работает). Обрати внимание: со знаком `$` после `::`.

### Скрипт № 3 — наследование от двух классов

```php
class BestClass extends RegularClass, BetterClass {
    public $name = "Лучший из лучших";
}
```

```
Parse error: syntax error, unexpected token ",", expecting "{"
```

**Что нарушено.** В PHP **нет множественного наследования**: после `extends` может стоять только **один** класс. Это синтаксическая ошибка — скрипт не запустится вообще, даже первая строка.

Зачем такой запрет: если в обоих родителях есть `$name` (здесь так и есть), непонятно, какой из них должен достаться наследнику.

**Куда исправлять:**

- выстроить цепочку: `BetterClass extends RegularClass`, а `BestClass extends BetterClass`. Тогда `BestClass` получит всё от обоих (проверено: `instanceof RegularClass` → `true`);
- или наследовать один класс, а общие методы вынести в **трейт** (`trait`) и подключить `use` внутри класса.

### Скрипт № 4 — функция вызывает саму себя

```php
namespace Strings;

function strlen($str) {
    return strlen($str);
}
echo strlen("Hi");
```

```
Fatal error: Allowed memory size of 268435456 bytes exhausted
```

Самый хитрый. Ошибка не говорит прямо, что не так. Разберём.

**Что происходит.** Внутри пространства имён `Strings` PHP ищет функцию по короткому имени `strlen` так:

1. сначала — `Strings\strlen` (в **текущем** пространстве);
2. только если её нет — встроенную глобальную `strlen`.

Мы сами объявили `Strings\strlen`. Поэтому `strlen($str)` **внутри** неё вызывает… её же. Та снова вызывает себя, и так бесконечно — **бесконечная рекурсия** (ЛР8). Каждый вызов занимает немного памяти, и когда память (256 МБ в MAMP) кончается — Fatal error.

**Куда исправлять.** Внутри функции явно позвать **глобальную** встроенную `strlen` — с обратной косой чертой в начале: `\strlen($str)`. `\` в начале имени означает «из глобального пространства, а не из текущего» (проверено: выводит `2`).

### Скрипт № 1 из второй части — конструктор не вызвался

```php
class SomeClass {
    private $name;
    function _construct($name) {
        $this->name = $name;
    }
}

$new_class = new SomeClass("Какое-то свойство");
var_dump($new_class);
```

```
object(SomeClass)#1 (1) { ["name":"SomeClass":private]=> NULL }
```

**Что нарушено.** `_construct` — **одно** подчёркивание. Конструктор называется `__construct` — **два**. Для PHP `_construct` — просто обычный метод с таким именем, автоматически при `new` он не вызывается. Аргумент `"Какое-то свойство"` никуда не попадает, а `$name` остаётся `NULL`.

При этом ошибки нет: PHP разрешает передать в `new` аргументы, даже если конструктора нет. Поэтому такую опечатку легко не заметить.

В «ожидаемом выводе» в задании написано `object(BestClass)` — это опечатка в методичке: класс называется `SomeClass`, и `var_dump` покажет именно `SomeClass`.

### Скрипт № 2 из второй части — параметр вместо свойства

```php
$name = "Пузослав";

class CatClass {
    public $name = "Васисуалий";
    public function say($name) {
        return "Привет, $name!";
    }
}

$obj = new CatClass();
echo $obj->say($name);   // Привет, Пузослав!  — а ожидали Васисуалия
```

**Что нарушено.** Внутри метода `$name` — это **параметр** метода, в который передали `"Пузослав"`. Свойство объекта — это **другая** переменная, и обращаются к нему только через `$this`: `$this->name`.

Важно для понимания: внутри метода переменные снаружи не видны (область видимости, ЛР8), и свойства тоже не видны «просто по имени» — только через `$this->`.

**Куда исправлять.** В строке приветствия использовать свойство объекта. В строке в двойных кавычках — с фигурными скобками: `"Привет, {$this->name}!"`. Параметр `$name` тогда не нужен.

## Задание 2 — четыре принципа ООП

> Создайте класс, который бы демонстрировал основные принципы ООП (инкапсуляция, полиморфизм, наследование, абстракция). Объясните, в чём суть каждого из этих принципов.

Нужно не просто написать класс, а уметь **показать пальцем**, где в нём каждый принцип. Ниже — каждый принцип с маленьким примером. Свой класс придумай сам: банковский счёт, транспорт, фигуры, животные — что угодно, где есть «общее» и «разновидности».

### Инкапсуляция — «спрятать внутренности»

Данные объекта закрыты (`private` / `protected`), а работать с ними можно только через методы, которые следят за правилами.

```php
class BankAccount
{
    private float $balance = 0;

    public function deposit(float $amount): void
    {
        if ($amount <= 0) {
            throw new Exception("Сумма должна быть положительной");
        }
        $this->balance += $amount;
    }

    public function getBalance(): float
    {
        return $this->balance;
    }
}
```

Снаружи нельзя написать `$acc->balance = -500`. Положить деньги можно только через `deposit`, а он не пропустит отрицательную сумму. Как кнопки банкомата: снаружи кнопки, внутрь — нельзя.

### Наследование — «взять готовое и дополнить»

Новый класс получает свойства и методы существующего (`extends`) и добавляет своё. Общий код пишется один раз — в родителе.

```php
class SavingsAccount extends BankAccount
{
    public function addInterest(float $percent): void { /* ... */ }
}
```

`SavingsAccount` умеет всё, что `BankAccount` (`deposit`, `getBalance`), плюс начислять проценты.

### Полиморфизм — «один вызов, разное поведение»

Разные классы реализуют **одинаковый** метод по-своему, а код, который его вызывает, о разнице не думает:

```php
abstract class Shape
{
    abstract public function area(): float;
}

class Circle extends Shape
{
    public function __construct(private float $r) {}
    public function area(): float { return M_PI * $this->r ** 2; }
}

class Square extends Shape
{
    public function __construct(private float $side) {}
    public function area(): float { return $this->side ** 2; }
}

$shapes = [new Circle(1), new Square(2)];
foreach ($shapes as $shape) {
    echo $shape->area(), "\n";   // у круга посчитается по-круговому, у квадрата — по-квадратному
}
```

`foreach` вызывает одно и то же `->area()` и не знает, круг перед ним или квадрат. «Поли-морф» — «много форм» одного и того же действия.

### Абстракция — «главное, без лишних деталей»

Выделить, **что** объект делает, и спрятать, **как**. В коде это абстрактные классы и интерфейсы: `Shape` выше говорит «у каждой фигуры есть площадь», не говоря, как её считать. Тот, кто пользуется фигурами, знает только про `area()`.

Бытовой пример: ты водишь машину через руль и педали — это абстракция. Как устроен двигатель, знать не нужно.

### Как связать в одном классе

Удобная схема для задания — абстрактный родитель и 2–3 наследника:

| Принцип | Где показать |
|---|---|
| абстракция | `abstract class` с абстрактным методом |
| наследование | наследники `extends` родителя, используют его общий метод |
| полиморфизм | `foreach` по массиву разных наследников, у всех вызывается один и тот же метод |
| инкапсуляция | `private` / `protected` свойства + методы с проверками |

### План задания 2

1. Придумать тему: «общее понятие» и 2–3 разновидности.
2. Абстрактный родитель: защищённые свойства, конструктор, абстрактный метод, обычный общий метод.
3. Наследники реализуют абстрактный метод по-разному.
4. Показать: массив разных объектов + `foreach` с одним вызовом; попытку изменить `private`-свойство снаружи — в `try/catch (Error $e)`.
5. Подписать на странице, где какой принцип.

## Задание 3 — класс `Book`: геттеры, сеттеры, автоинкремент, магические методы

> Создайте класс `Book`, имеющий следующие приватные поля: `$id`, `$title`, `$author`, `$year`, `$pageCount`. Осуществите доступ к ним через геттеры и сеттеры, но учтите, что:
>
> - свойство `$pageCount` должно быть доступно только для чтения и назначаться случайно в конструкторе класса;
> - свойство `$id` должно быть статическим и доступным только для чтения, оно автоматически увеличивается на единицу и присваивается новому объекту (то есть должен быть реализован автоинкремент).
>
> Реализуйте для класса магические методы `__get()`, `__set()`, `__toString()` и `__call()`.

### Геттеры и сеттеры — для `title`, `author`, `year`

Обычные пары `getTitle()` / `setTitle()` и т. д. (см. «Основу»). В сеттерах — проверки: название не пустое, год не больше текущего.

### «Только для чтения» — геттер без сеттера

Для `$pageCount` и `$id` пишется **только геттер**. Сеттера нет — снаружи изменить нельзя. Внутри класса значение записывается один раз — в конструкторе.

Есть и встроенный механизм PHP 8.1 — модификатор **`readonly`**:

```php
class Book
{
    private readonly int $pageCount;

    public function __construct()
    {
        $this->pageCount = rand(100, 1000);   // записать можно ровно один раз
    }
}
```

Вторая запись — даже изнутри класса — выдаст `Error: Cannot modify readonly property` (проверено). Это защита от случайной перезаписи. `readonly` требует, чтобы у свойства был указан тип.

`rand(100, 1000)` — случайное число (ЛР4). Это и есть «назначается случайно в конструкторе».

### Автоинкремент `id` — статический счётчик

В условии сказано «`$id` должно быть статическим». Но если сделать **сам** `$id` статическим, он станет **один на все книги**, и у всех книг будет одинаковый `id` — последний выданный. А нужно, чтобы у каждой книги был свой номер.

Поэтому обычно делают **два** свойства:

```php
class Book
{
    private static int $lastId = 0;   // статический СЧЁТЧИК — один на весь класс
    private int $id;                  // номер ЭТОЙ книги — свой у каждой

    public function __construct()
    {
        self::$lastId++;              // счётчик +1
        $this->id = self::$lastId;    // записать текущий номер в книгу
    }

    public function getId(): int
    {
        return $this->id;
    }
}

$a = new Book();   // id = 1
$b = new Book();   // id = 2
$c = new Book();   // id = 3
```

Проверено: три объекта получили `id` 1, 2, 3. Статический счётчик помнит, сколько книг уже создано, и каждая новая берёт следующий номер. Это то же самое, что `AUTO_INCREMENT` в базе данных (ЛР11), только вручную.

Для защиты: объясни, что «статическим» в решении является **счётчик**, а сам `id` у каждой книги свой, иначе автоинкремент невозможен.

### Магические методы

**Магические методы** — методы с именами на `__`, которые PHP вызывает **сам** в особых ситуациях. `__construct` — один из них. Задание просит ещё четыре.

#### `__get($name)` — чтение недоступного свойства

```php
public function __get($name)
{
    return $this->$name;
}
```

Вызывается, когда снаружи **читают** свойство, которое недоступно: `private`, `protected` или вообще не существует.

```php
$book = new Book("Дюна");
echo $book->title;   // title приватное → PHP вызывает __get("title")
```

В `$name` приходит **строка** — имя свойства (`"title"`). `$this->$name` — обращение к свойству по имени из переменной: если `$name = "title"`, это то же, что `$this->title`.

Для **публичных** свойств `__get` не вызывается — их PHP читает напрямую (проверено).

#### `__set($name, $value)` — запись в недоступное свойство

```php
public function __set($name, $value)
{
    // здесь решаем, разрешить ли запись и с какими проверками
}
```

Вызывается, когда снаружи **записывают** в недоступное свойство: `$book->title = "Хоббит"` → `__set("title", "Хоббит")`.

Внимание: `__get` + `__set` без проверок, которые просто читают и пишут любое свойство, **отменяют** инкапсуляцию — `private` становится как `public`. Так что внутри них стоит:

- разрешать только нужные свойства;
- для `id` и `pageCount` — **отказывать** в записи (они только для чтения): выбросить исключение;
- для остальных — вызывать сеттер, чтобы сработали его проверки.

#### `__toString()` — объект как строка

```php
public function __toString(): string
{
    return "Книга «{$this->title}»";
}
```

Вызывается, когда объект используют как строку: `echo $book`, `"Читаю: " . $book` (проверено). Без `__toString` такой `echo` выдал бы ошибку «Object of class Book could not be converted to string». Должен **вернуть** строку, а не вывести её.

#### `__call($name, $arguments)` — вызов несуществующего метода

```php
public function __call($name, $arguments)
{
    return "Метода $name нет";
}

$book->fly(1, 2);   // метода fly нет → __call("fly", [1, 2])
```

Вызывается, когда вызывают метод, которого нет (или он недоступен). `$name` — имя метода, `$arguments` — **массив** переданных аргументов.

Применения: понятное сообщение вместо Fatal error, или «универсальные» методы. Например, `getTitle()`, `getAuthor()`, `getYear()` можно не писать по отдельности: в `__call` проверить, что имя начинается на `get` (`str_starts_with`, ЛР5), отрезать `get`, привести первую букву к нижнему регистру (`lcfirst`) и вернуть соответствующее свойство.

Для статических методов есть пара — `__callStatic`.

#### Таблица — когда что срабатывает

| Действие снаружи | Магический метод |
|---|---|
| `new Book(...)` | `__construct` |
| `echo $book->title` (свойство недоступно) | `__get("title")` |
| `$book->title = "X"` (свойство недоступно) | `__set("title", "X")` |
| `echo $book` | `__toString()` |
| `$book->fly(1, 2)` (метода нет) | `__call("fly", [1, 2])` |
| `isset($book->title)` (свойство недоступно) | `__isset("title")` — если не написать, будет `false` (проверено) |

### План задания 3

1. Пять `private`-свойств + статический счётчик.
2. Конструктор: принять название, автора, год; выдать `id` от счётчика; `pageCount = rand(...)`.
3. Геттеры для всех, сеттеры — только для `title`, `author`, `year`, с проверками.
4. Четыре магических метода. В `__set` — отказ для `id` и `pageCount`.
5. Показать на странице: создать несколько книг (`id` растут), прочитать через геттер и через `__get`, попытаться изменить `pageCount` (поймать ошибку), `echo $book`, вызвать несуществующий метод.

## Задание 4 — класс `Library`: выдача и возврат книг

> Создайте класс `Library`, реализующий систему аренды книг. В данном классе должны быть приватные свойства `$name` и `$books` (каждая книга – экземпляр класса `Book`). Реализуйте следующие методы:
>
> - `borrow()` и `return()`, с помощью которых книгу можно взять, а после вернуть;
> - `addBook()` – для добавления новых книг в библиотеку;
> - `show($mode = 0)` – для отображения всех книг в библиотеке, которая при `$mode = 0` возвращает все книги, `$mode = 1` – книги в наличии, `$mode = 2` – недоступные на данный момент книги;
> - `findBook($searchTitle)` – для поиска книги по названию.
>
> Предусмотрите обработку ошибок (например, нельзя взять книгу, которую уже взяли). По желанию можете добавить в книгу свойство `$amount`, отражающее количество экземпляров данной книги.

### Массив объектов

`$books` — обычный массив (ЛР6), только элементы в нём не строки, а объекты `Book`:

```php
private array $books = [];

public function addBook(Book $book): void
{
    $this->books[] = $book;
}
```

`Book $book` в параметре — **тип-класс**: передать можно только объект `Book` (или его наследника). Попытка передать строку — `TypeError`.

Удобно хранить книги с ключом `id`: `$this->books[$book->getId()] = $book`. Тогда книгу легко найти по номеру.

### Где хранить «книга выдана»

Нужно знать, в наличии книга или нет. Варианты:

- свойство в `Book`: `private bool $isAvailable = true` + методы для изменения;
- или по совету задания — `$amount`, количество экземпляров: взяли — `-1`, вернули — `+1`, в наличии — если `> 0`.

### Метод с именем `return`

`return` — ключевое слово PHP (ЛР8). Но с PHP 7.0 ключевые слова **можно** использовать как имена методов, потому что метод всегда вызывается через `->`, и PHP понимает, что это имя, а не команда. Проверено: `public function return(...)` и вызов `$library->return(...)` работают.

Внутри метода `return` пишется как обычно — чтобы вернуть значение.

### Обработка ошибок — исключения

Ситуации, когда операция невозможна:

| Ситуация | Где |
|---|---|
| книги с таким названием / `id` нет | `borrow`, `return`, `findBook` |
| книгу уже взяли (экземпляров 0) | `borrow` |
| возвращают книгу, которую не брали | `return` |
| неверный `$mode` | `show` |

В каждом таком месте — `throw new Exception("понятный текст")`, а вызывающий код — в `try / catch`. Метод сообщает о проблеме, страница решает, как её показать.

Можно завести **свой класс ошибки** — `class LibraryException extends Exception {}` — и ловить именно его. Так ошибки библиотеки не перепутаются с другими.

### `show($mode)` — выбор через `match`

Три режима — классическая задача для `match` (ЛР7):

```php
return match ($mode) {
    0 => $this->books,
    1 => /* только в наличии */,
    2 => /* только выданные */,
    default => throw new Exception("Неизвестный режим $mode"),
};
```

Отбор «только в наличии» — `array_filter` (ЛР6) с функцией, которая проверяет книгу: `fn(Book $b) => $b->isAvailable()`.

В условии сказано, что `show` **возвращает** книги. Значит, метод возвращает массив, а выводит его на страницу уже код снаружи. Это хорошее правило: класс работает с данными, а HTML — отдельно.

### `findBook($searchTitle)` — поиск по названию

Как поиск в ЛР9 и ЛР11: часть названия, без учёта регистра — `mb_stripos($book->getTitle(), $searchTitle) !== false` (ЛР9). Решить заранее, что вернуть: все найденные книги массивом, первую найденную или исключение, если ничего нет.

### План задания 4

1. В `Book` (из задания 3) — признак наличия или `$amount` и методы для его изменения.
2. `Library`: `private $name`, `private array $books`, конструктор с названием.
3. `addBook(Book $book)`.
4. `borrow` и `return` — по `id` или названию, с исключениями.
5. `show($mode)` через `match` + `array_filter`.
6. `findBook` через `mb_stripos`.
7. Показать на странице: добавить книги, взять одну, `show(1)` и `show(2)`, попытаться взять ту же книгу ещё раз (поймать ошибку), вернуть.

## Задание 5 — абстрактный `Book`, наследники, интерфейс `Digital`

> Измените класс `Book` таким образом, чтобы он стал базовым абстрактным классом. Добавьте в него абстрактный метод `getGenre()`, который должен быть реализован в потомках класса. Создайте дочерние классы `FictionBook()` и `NonFictionBook()` (`getGenre()` для них должен возвращать соответственно `"Художественная литература"` и `"Нехудожественная литература"`). Также создайте интерфейс `Digital`, определяющий методы `getFormat()` для получения формата файла и `getSize()` для получения размера файла. Класс `Book` должен реализовывать данный интерфейс.

### Что меняется в `Book`

1. `class Book` → `abstract class Book`.
2. Добавить `abstract public function getGenre(): string;` — **без тела**.
3. Теперь `new Book(...)` невозможен — создаются только `FictionBook` и `NonFictionBook`.

Всё, что было в `Book` (свойства, геттеры, счётчик `id`, магические методы), **остаётся** — наследники получат это готовым. Это и есть смысл базового класса.

### Наследники

```php
class FictionBook extends Book
{
    public function getGenre(): string
    {
        return "Художественная литература";
    }
}
```

`NonFictionBook` — так же, со своей строкой. Наследник обязан реализовать `getGenre`. Если забыть — `Class FictionBook contains 1 abstract method and must therefore be declared abstract or implement the remaining methods (Book::getGenre)` (проверено): PHP прямо пишет, какой метод не реализован.

В задании имена написаны со скобками — `FictionBook()`, — но это просто имена классов. Скобки ставятся при `new FictionBook(...)`.

### Интерфейс `Digital` и `implements`

```php
interface Digital
{
    public function getFormat(): string;
    public function getSize(): int;
}

abstract class Book implements Digital
{
    // ...
}
```

Тонкость (проверено): абстрактный класс, реализующий интерфейс, **не обязан** сам писать методы интерфейса. Они считаются абстрактными и переходят к наследникам. Тогда `getFormat()` и `getSize()` реализуют `FictionBook` и `NonFictionBook`, как и `getGenre()`.

Если формат и размер у всех книг считаются одинаково — можно реализовать их прямо в `Book`. Тогда наследникам писать их не нужно. Оба варианта выполняют условие «`Book` реализует `Digital`».

Откуда брать формат и размер: свойства `$format` (`"pdf"`, `"epub"`) и `$fileSize` в конструкторе. Или, например, размер можно считать от `$pageCount`.

### Проверить на странице

- создать по объекту каждого наследника, вывести `getGenre()`, `getFormat()`, `getSize()`;
- `$book instanceof Book` и `$book instanceof Digital` → оба `true` (проверено);
- `new Book(...)` в `try / catch (Error $e)` → `Cannot instantiate abstract class Book`;
- класс `Library` из задания 4 продолжает работать: в нём тип параметра `Book`, а наследники — тоже `Book`. Это полиморфизм в действии.

## Задание 6 — пространства имён

> Создайте несколько произвольных классов и функций в одном файле, имеющем какое-либо пространство имён. Каждый класс поместите в своём подпространстве. Вызовите методы и классы в другом файле.

### Пространство и подпространство

Пространства имён устроены как папки — уровни разделяются **обратной** косой чертой `\`:

```
Shop                    — пространство
├── Shop\Products       — подпространство
│   └── Book            — полное имя класса: Shop\Products\Book
└── Shop\Users
    └── Customer        — Shop\Users\Customer
```

### Несколько пространств в одном файле — синтаксис со скобками

Задание просит всё в **одном** файле, но каждый класс — в **своём** подпространстве. Для этого пространства пишут блоками в фигурных скобках:

```php
<?php
namespace Shop\Products {
    class Book { /* ... */ }

    function hello(): string
    {
        return "hello из " . __NAMESPACE__;
    }
}

namespace Shop\Users {
    class Customer { /* ... */ }

    const ROLE = "user";
}
```

Проверено. Правила:

- `namespace` должен быть **первой** командой файла (после `<?php`, ещё до любого HTML);
- в одном файле **не смешивают** вариант со скобками и без скобок;
- в пространстве живут классы, интерфейсы, функции и константы. Переменные — нет.

`__NAMESPACE__` — магическая константа: имя текущего пространства (`"Shop\Products"`). `__CLASS__` — полное имя текущего класса.

### Вызов из другого файла

Сначала файл подключают (`require_once`, ЛР7). Потом к классам обращаются одним из способов:

**1. Полным именем** — с `\` в начале:

```php
require_once "lib.php";
$book = new \Shop\Products\Book();
echo \Shop\Products\hello();
```

**2. Через `use`** — «импорт» имени, чтобы дальше писать коротко:

```php
require_once "lib.php";

use Shop\Products\Book;               // класс
use Shop\Users\Customer as Client;    // класс под другим именем — псевдоним
use function Shop\Products\hello;     // функция — слово function обязательно
use const Shop\Users\ROLE;            // константа — слово const обязательно

$book = new Book();
$client = new Client();
echo hello();
echo ROLE;
```

| Запись | Значит |
|---|---|
| `use Полное\Имя;` | дальше можно писать просто `Имя` |
| `use Полное\Имя as Другое;` | псевдоним — например, если в файле уже есть свой `Customer` |
| `use function ...;` / `use const ...;` | импорт функции / константы |
| `\Имя` в начале | «от корня» — из глобального пространства (как `\strlen` в задании 1) |
| `Book::class` | строка с полным именем класса: `"Shop\Products\Book"` (проверено) |

`use` пишут в начале файла, после `namespace` (если он есть) и до остального кода. `use` только делает имя короче — файл он **не подключает**. `require_once` всё равно нужен.

### Как это связано с заданием 1 (скрипт № 4)

Внутри пространства PHP ищет короткое имя функции сначала в текущем пространстве, потом в глобальном. Поэтому своя функция `strlen` в `Strings` «перекрыла» встроенную. `\strlen` — явное указание «встроенную, из корня».

### Где это используется в жизни

В любом современном PHP-проекте каждый класс лежит в своём пространстве, совпадающем с папкой: `App\Models\Book` → `app/Models/Book.php`. Файлы подключает автозагрузчик (Composer), и `require` руками не пишут. В лабе всё в одном файле — чтобы показать сам механизм.

### План задания 6

1. Файл (например, `lib.php`) с `namespace ... { }` блоками: 2–3 подпространства, в каждом свой класс, плюс пара функций.
2. Другой файл: `require_once` + `use` (обычный, с `as`, `use function`).
3. Создать объекты, вызвать методы и функции — один раз полным именем, остальные через `use`.
4. Вывести `Класс::class`, чтобы было видно полные имена.

## Ответы на контрольные вопросы

### 1. Что такое объектно-ориентированное программирование? Перечислите основные принципы ООП.

Подход, при котором программа строится из **объектов** — сущностей, которые объединяют данные (свойства) и действия над ними (методы). Объекты создаются по **классам**. Четыре принципа:

- **инкапсуляция** — данные скрыты внутри объекта, доступ только через его методы;
- **наследование** — класс получает свойства и методы другого класса и дополняет их;
- **полиморфизм** — разные классы по-разному реализуют один и тот же метод, а вызывающий код работает с ними одинаково;
- **абстракция** — выделение главного (что объект делает) без деталей реализации (как).

### 2. Что такое свойство (поле), метод, объект, класс?

- **Класс** — описание (чертёж): какие у объектов будут свойства и методы.
- **Объект** — конкретный экземпляр класса, создаётся через `new`.
- **Свойство** (поле) — переменная внутри объекта, хранит его данные: `$book->title`.
- **Метод** — функция внутри класса, действие объекта: `$book->info()`.

### 3. Какие есть модификаторы доступа у полей класса?

- `public` — доступно везде;
- `protected` — внутри класса и его наследников;
- `private` — только внутри самого класса.

Ещё бывают `static` (свойство класса, а не объекта) и `readonly` (записать можно только один раз). Это не модификаторы доступа, но пишутся рядом с ними.

### 4. Какой метод называют статическим? Как в нестатическом методе получить значение статической переменной? А в дочернем классе?

**Статический** метод (`static`) принадлежит классу, а не объекту. Вызывается без создания объекта: `Класс::метод()`. Внутри него нет `$this`.

Получить статическое свойство:

- в нестатическом методе того же класса — `self::$свойство` (или `static::$свойство`);
- в дочернем классе — `parent::$свойство` (значение из родителя), `self::$свойство` / `static::$свойство` (если наследник своё не объявлял — тоже значение родителя);
- снаружи — `Класс::$свойство`.

`self::` указывает на класс, где написан код, `static::` — на класс, у которого метод реально вызван. Разница видна, когда наследник переопределил статическое свойство.

### 5. Какой класс называют абстрактным? Метод?

**Абстрактный класс** (`abstract class`) — класс-основа, объекты которого создавать нельзя. Только наследовать. Может содержать и обычные, и абстрактные методы.

**Абстрактный метод** — метод без тела, только объявление. Каждый наследник обязан его реализовать. Если в классе есть хоть один абстрактный метод, класс должен быть абстрактным.

### 6. Что такое интерфейс?

Список методов, которые класс обязуется реализовать. Методы без тел, без свойств. Класс подключает интерфейс словом `implements` и должен написать все его методы. Один класс может реализовывать несколько интерфейсов, а наследовать — только один класс. Интерфейс описывает, что объект **умеет**, не говоря, как.

## Шпаргалка

| Конструкция | Что делает | Пример |
|---|---|---|
| `class Имя { }` | объявить класс | `class Book { }` |
| `new Имя(...)` | создать объект | `$b = new Book("Дюна")` |
| `->` | свойство / метод объекта | `$b->title`, `$b->info()` |
| `$this` | текущий объект внутри метода | `$this->title` |
| `__construct(...)` | конструктор, вызывается при `new` | **два** подчёркивания |
| `public function __construct(private string $t)` | конструктор + свойство одной строкой | PHP 8 |
| `public` / `protected` / `private` | доступ: всем / классу и наследникам / только классу | |
| `readonly` | записать можно один раз | `private readonly int $pages` |
| `static` | свойство / метод класса | `private static int $count` |
| `Класс::$св`, `Класс::метод()` | обращение к статическому | `Counter::total()` |
| `self::` / `static::` / `parent::` | этот класс / класс вызова / родитель | `self::$count++` |
| `const` в классе | константа класса | `Book::MAX_PAGES` |
| `extends` | наследовать (только один класс) | `class Cat extends Animal` |
| `abstract class` | нельзя создать объект | `abstract class Shape` |
| `abstract function f();` | метод без тела | реализует наследник |
| `interface` + `implements` | обязательный набор методов | `class EBook implements Digital` |
| `trait` + `use` в классе | подмешать методы | вместо множественного наследования |
| `instanceof` | объект этого класса / наследника? | `$b instanceof Book` |
| `throw new Exception("...")` | выбросить ошибку | |

| `__get($name)` | чтение недоступного свойства | `$b->title` при `private` |

| `__toString()` | объект как строка | `echo $b` |

| `__isset($name)` | `isset` для недоступного свойства | |
| `$this->$name` | свойство по имени из переменной | в `__get` / `__set` |

| `use function` / `use const` | импорт функции / константы | |
| `\имя` | из глобального пространства | `\strlen($s)` |
| `Класс::class` | полное имя класса строкой | `"Shop\Products\Book"` |
| `__NAMESPACE__` / `__CLASS__` | текущее пространство / класс | |
