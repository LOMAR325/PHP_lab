Тема: **работа с файловой системой**. PHP умеет не только выводить HTML, но и работать с файлами на сервере, как Finder: смотреть, что лежит в папке, узнавать размер и дату файла, копировать, перемещать, удалять, читать и дописывать текст.

## 0. Основа

### Файлы и папки

Файловая система — дерево: папки содержат файлы и другие папки.

```
labwork12/
├── lab12.php
├── files/
│   ├── photo.png
│   ├── заметка.txt
│   └── Картинки/
│       ├── logo.PNG
│       └── Отпуск/
│           └── sea1.jpg
```

В PHP папку часто называют **директорией** (directory) — отсюда имена функций: `is_dir`, `mkdir`, `scandir`.

### Путь к файлу

**Путь** — адрес файла в этом дереве. Части разделяются `/`.

| Вид | Пример | Откуда считается |
|---|---|---|
| **абсолютный** | `/Users/User/PHP/labwork12/files/photo.png` | от корня диска `/` |
| **относительный** | `files/photo.png` | от **текущей папки** |

Специальные имена:

- `.` — «эта папка»: `./files` = `files`;
- `..` — «папка уровнем выше»: из `labwork12` путь `../labwork11` ведёт в соседнюю папку.

### Относительно чего считаются пути — `__DIR__`

Относительный путь считается от **текущей рабочей папки** скрипта. Когда страницу открывают через MAMP, это обычно папка самого скрипта. Но если файл подключён через `require` из другой папки, «текущая» может оказаться не той, которую ожидаешь.

Надёжный способ — строить путь от `__DIR__`:

```php
echo __DIR__;                      // /Users/User/PHP/labwork12
$folder = __DIR__ . "/files";      // всегда правильный путь к files
```

`__DIR__` — **магическая константа**: PHP подставляет в неё абсолютный путь к папке **того файла, в котором она написана**. Не меняется, откуда бы файл ни подключали.

### Файлы и PHP-скрипт — разные вещи

Функции этой лабы работают с файлами **на сервере** — в нашем случае на твоём Mac, потому что сервер MAMP запущен на нём. Браузер их не видит, пока PHP не выведет информацию о них в HTML.

### Время в файловой системе — числом

Все функции «когда изменён файл» возвращают **Unix-время**: число секунд с 1 января 1970 года — то же, что `time()` (ЛР9). Чтобы показать его человеку — `date()` (ЛР8):

```php
date("d.m.Y H:i:s", 1793277600);   // "29.10.2026 ..."
```

Не забудь `date_default_timezone_set("Europe/Minsk")` (ЛР8), иначе время будет по UTC.

### Кириллица в именах файлов

Работает, но помни про ЛР5: русская буква — 2 байта. Для `strlen`, `substr` по имени файла нужны `mb_`-версии. Функции файловой системы (`file_exists`, `copy` и др.) с кириллическими путями работают нормально.

## Задание 1 — информация о файлах

> Добавьте в отдельную папку несколько изображений (например, `.jpeg`, `.png`), текстовых файлов (например, `.txt`, `.docx` или `.odt`) и других файлов (например, `.mp3`). Получите и выведите для них:
>
> - тип файла;
> - MIME-тип содержимого файла;
> - размер файла;
> - имя файла и его расширение;
>
> А также получите и выведите время:
>
> - последнего доступа к файлу;
> - последнего изменения файла.

### `file_exists($путь)` / `is_file($путь)` / `is_dir($путь)` — что лежит по пути

```php
file_exists("files/photo.png");   // true — что-то есть (файл или папка)
is_file("files/photo.png");       // true — это файл
is_dir("files/photo.png");        // false — это не папка
is_dir("files");                  // true
file_exists("nope.txt");          // false
```

Возвращают `true` / `false`. Их вызывают **перед** работой с файлом, чтобы не получить предупреждение «No such file or directory».

### `filetype($путь)` — тип элемента файловой системы

```php
filetype("files/photo.png");   // "file"
filetype("files/Картинки");    // "dir"
```

Возвращает строку:

| Значение | Что это |
|---|---|
| `"file"` | обычный файл |
| `"dir"` | папка |
| `"link"` | символическая ссылка (ярлык) |

Обрати внимание: `filetype` **не различает** картинку и музыку — для неё всё это `"file"`. Поэтому «тип файла» из задания можно понимать двумя способами:

1. «файл или папка» — `filetype`;
2. «изображение, текст, аудио» — по первой части MIME-типа (см. ниже).

Можно вывести оба — так точно будет ответ на любое понимание.

### `mime_content_type($путь)` — MIME-тип по содержимому

```php
mime_content_type("files/photo.png");   // "image/png"
mime_content_type("files/cat.jpg");     // "image/jpeg"
mime_content_type("files/заметка.txt"); // "text/plain"
mime_content_type("files/Картинки");    // "directory"
```

**MIME-тип** — стандартное название вида содержимого: `тип/подтип`. Тот же, что браузер получает от сервера, чтобы понять, показывать картинку, играть музыку или скачивать файл.

| MIME-тип | Что это |
|---|---|
| `image/png`, `image/jpeg` | изображения |
| `text/plain` | обычный текст |
| `audio/mpeg` | mp3 |
| `application/pdf` | PDF |
| `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | `.docx` |
| `application/octet-stream` | «просто байты» — не удалось определить |

**Главное — определяется по содержимому, а не по расширению.** PHP заглядывает в первые байты файла: у PNG там всегда сигнатура `‰PNG`, у JPEG — свои байты, и так далее.

Проверено: файл `fake.mp3`, внутри которого просто текст «это не музыка», PHP определил как **`text/plain`**. Расширение `.mp3` его не обмануло. Поэтому в задании нужны **настоящие** файлы: если переименовать `.txt` в `.mp3`, MIME-тип останется текстовым.

Первая часть MIME-типа (до `/`) — это и есть «тип» в человеческом смысле: `image` — изображение, `text` — текст, `audio` — аудио. Достать её — `explode("/", $mime)[0]` (ЛР5).

Второй способ — класс `finfo`, делает то же самое:

```php
$finfo = new finfo(FILEINFO_MIME_TYPE);
echo $finfo->file("files/photo.png");   // "image/png"
```

Обе функции работают через расширение PHP `fileinfo`. В MAMP оно включено (проверено).

### `filesize($путь)` — размер в байтах

```php
filesize("files/photo.png");   // 70
```

Возвращает размер файла в **байтах**. Для папки размер содержимого не считает — только для файлов.

Человеку удобнее «11.7 КБ», а не «12000». Перевод: в 1 КБ — 1024 байта, в 1 МБ — 1024 КБ.

```php
round(12000 / 1024, 1) . " КБ";   // "11.7 КБ"
```

Хорошая идея — написать маленькую функцию (ЛР8), которая сама выбирает Б, КБ или МБ: делить на 1024, пока число больше 1024, и считать, сколько раз поделили.

### `pathinfo($путь)` — разобрать путь на части

```php
print_r(pathinfo("/путь/к/cat 2024.jpg"));
```

```
Array
(
    [dirname]   => /путь/к          // папка
    [basename]  => cat 2024.jpg     // имя с расширением
    [extension] => jpg              // расширение без точки
    [filename]  => cat 2024         // имя без расширения
)
```

Вторым аргументом можно попросить одну часть:

```php
pathinfo("photo.png", PATHINFO_EXTENSION);   // "png"
pathinfo("photo.png", PATHINFO_FILENAME);    // "photo"
```

Особые случаи (проверено):

| Путь | `extension` | Почему |
|---|---|---|
| `archive.tar.gz` | `"gz"` | расширение — только после **последней** точки |
| `README` | `""` | точки нет — расширения нет |

Это то, что задание называет «имя файла и его расширение».

### `basename($путь)` и `dirname($путь)` — имя и папка

```php
basename("/a/b/c.txt");           // "c.txt"
basename("/a/b/c.txt", ".txt");   // "c"
dirname("/a/b/c.txt");            // "/a/b"
```

`basename` был в ЛР9. `dirname` — обратное: всё, **кроме** последней части. Короче, чем `pathinfo`, когда нужна одна часть.

### `filemtime($путь)` — время последнего изменения

```php
date("d.m.Y H:i:s", filemtime("files/заметка.txt"));
```

Когда **содержимое** файла последний раз менялось. Возвращает Unix-время.

### `fileatime($путь)` — время последнего доступа

```php
date("d.m.Y H:i:s", fileatime("files/заметка.txt"));
```

Когда файл последний раз **читали** (открывали).

Подвох, который стоит знать для защиты (проверено на macOS): после чтения файла время доступа **не изменилось**. Операционные системы часто не обновляют время доступа при каждом чтении — это лишняя запись на диск при каждом открытии любого файла. macOS и многие Linux-серверы обновляют его редко или вообще не обновляют. Поэтому `fileatime` нередко совпадает со временем создания или изменения. Это не ошибка в коде.

### `filectime($путь)` — время изменения информации о файле

Есть третья функция: когда менялось **описание** файла (имя, права) или содержимое. Её путают со «временем создания», но на macOS и Linux это не так. В задании не нужна — просто чтобы не перепутать.

| Функция | Буква | Что |
|---|---|---|
| `fileatime` | **a** — access | последний доступ (чтение) |
| `filemtime` | **m** — modify | последнее изменение содержимого |
| `filectime` | **c** — change | последнее изменение информации о файле |

### Как перебрать все файлы папки

Список файлов папки даёт `scandir` (подробно — в задании 2):

```php
$files = array_diff(scandir(__DIR__ . "/files"), [".", ".."]);
foreach ($files as $name) {
    $path = __DIR__ . "/files/" . $name;
    // здесь — все функции выше для $path
}
```

Каждой функции нужен **путь** к файлу (`files/photo.png`), а не просто имя (`photo.png`). Иначе PHP будет искать файл в текущей папке и не найдёт. Частая ошибка.

2. Получить список файлов (`scandir` + `array_diff`).
3. Для каждого собрать: `filetype`, `mime_content_type`, `filesize` (лучше в КБ), `pathinfo` (имя + расширение), `fileatime` и `filemtime` через `date`.
4. Вывести таблицей `<table>` (как в ЛР2, задание 4): строка — файл, столбец — характеристика.

## Задание 2 — структура папок в массив, поиск по папке

> Создайте папку, содержащую подпапки, например, `Картинки`, `Музыка` и `Видео`. Добавьте в папки несколько соответствующих файлов. В ассоциативный массив, структура которого динамически подстраивается под структуру папок, занесите информацию о содержимом папок, например, так:
>
> ```php
> $folders = [
>     "Музыка" => [
>         "So Happy – Theory of a Deadman.mp3",
>         "Show Me What Your Lights Mean – Electric Six.flac"
>     ]
> ];
> ```
>
> В этой же папке найдите и выведите на экран:
>
> - все файлы `.jpg`;
> - все файлы, у которых есть цифры в названии;
> - все названия папок.

### `scandir($папка)` — содержимое папки

```php
print_r(scandir("files"));
```

```
Array
(
    [0] => .
    [1] => ..
    [2] => cat 2024.jpg
    [3] => fake.mp3
    [4] => photo.png
    [5] => Картинки
    [6] => Музыка
    [7] => заметка.txt
)
```

Возвращает массив **имён** (не путей) всего, что лежит в папке: и файлов, и подпапок. Только **один уровень** — что внутри `Картинки`, не показывает.

Две особенности:

- всегда есть **`.` и `..`** — «эта папка» и «папка выше». Их почти всегда выбрасывают;
- имена **отсортированы по алфавиту**. Латиница идёт раньше кириллицы.

### Убрать `.` и `..` — `array_diff`

```php
$items = array_diff(scandir("files"), [".", ".."]);
```

`array_diff` (ЛР6) — «элементы первого массива, которых нет во втором». Ключи сохраняются (будут 2, 3, 4…). Если нужны 0, 1, 2… — обернуть в `array_values` (ЛР6).

### `glob($шаблон, $флаги)` — найти файлы по шаблону

```php
glob("files/*.jpg");                       // ["files/cat 2024.jpg"]
glob("files/*", GLOB_ONLYDIR);             // ["files/Картинки", "files/Музыка"]
glob("files/*.{jpg,png}", GLOB_BRACE);     // jpg и png вместе
```

Возвращает массив **путей** (вместе с папкой, в отличие от `scandir`), подходящих под шаблон. `.` и `..` не возвращает.

Специальные символы шаблона — это **не** регулярные выражения (ЛР10), а более простые «маски», как в поиске файлов:

| Символ | Значит | Пример |
|---|---|---|
| `*` | любое количество любых символов | `*.jpg` — всё, что кончается на `.jpg` |
| `?` | ровно один любой символ | `photo?.png` — `photo1.png`, `photoA.png` |
| `[abc]` | один символ из набора | `img[0-9].png` |
| `{a,b}` | один из вариантов — только с `GLOB_BRACE` | `*.{jpg,jpeg}` |

Флаги:

| Флаг | Что делает |
|---|---|
| `GLOB_ONLYDIR` | только папки — готовый ответ на «все названия папок» |
| `GLOB_BRACE` | разрешить `{a,b}` |

Если ничего не найдено — **пустой массив**.

### Подвох 1: регистр расширения

```php
glob("files/Картинки/*.png");   // [] — пусто! А там лежит logo.PNG
```

Проверено: `glob` различает `png` и `PNG`. Фотографии с телефона часто называются `IMG_1234.JPG` — большими буквами. Варианты:

- шаблон с обоими вариантами: `*.{jpg,JPG,jpeg,JPEG}` + `GLOB_BRACE`;
- или взять все файлы и сравнить расширение без учёта регистра: `strtolower(pathinfo($name, PATHINFO_EXTENSION)) === "jpg"` (`strtolower` — ЛР5).

### Подвох 2: `glob` смотрит только один уровень

`glob("files/*.jpg")` не найдёт `files/Картинки/Отпуск/sea1.jpg` — он во вложенной папке. Если нужны файлы во всех подпапках — рекурсивный обход (задание 4) и проверка расширения у каждого файла.

### «Цифры в названии» — `preg_match`

Регулярные выражения из ЛР10:

```php
preg_match('/\d/', "cat 2024.jpg");   // 1 — цифра есть
preg_match('/\d/', "photo.png");      // 0 — нет
```

`\d` — любая цифра. Отфильтровать список — `array_filter` (ЛР6):

```php
$withDigits = array_filter($items, fn($name) => preg_match('/\d/', $name));
```

Если цифры не должны считаться в расширении (`.mp3` — там тройка!), проверяй имя **без** расширения: `pathinfo($name, PATHINFO_FILENAME)`. Проверено: без этого `fake.mp3` попадает в «файлы с цифрами».

### Массив «по структуре папок» — рекурсия

Главная часть задания. Массив должен **сам** подстраиваться под папки: добавил подпапку `Видео/2024` — в массиве появилось `"Видео" => ["2024" => [...]]`, без правок кода.

Это задача на **рекурсию** (ЛР8, задание 2 — подсчёт элементов вложенного массива). Идея функции:

```
описать(папка):
    результат = []
    для каждого имени в папке (без . и ..):
        если это папка  → результат[имя] = описать(эта подпапка)   — функция вызывает сама себя
        если это файл   → добавить имя в результат
    вернуть результат
```

Что получается (проверено на такой функции):

```
Array
(
    [0] => cat 2024.jpg
    [1] => fake.mp3
    [2] => photo.png
    [Картинки] => Array
        (
            [0] => logo.PNG
            [Отпуск] => Array
                (
                    [0] => sea1.jpg
                )
        )
    [Музыка] => Array
        (
            [0] => song.mp3
        )
    [3] => заметка.txt
)
```

Ровно формат из задания: папка — **ключ** со строковым именем, файлы — значения с номерами. Это смешанный массив со строковыми и целыми ключами (ЛР2, задание 7).

Две ошибки, которые почти все делают:

1. **Забыть убрать `.` и `..`.** Тогда функция зайдёт в `.` («эта же папка»), потом снова в `.`… — бесконечная рекурсия и Fatal error.
2. **Передать в `is_dir` имя, а не путь.** `is_dir("Отпуск")` ищет папку `Отпуск` в текущей папке скрипта, а она внутри `Картинки`. Нужно `is_dir("$папка/$имя")`.

Вывести такой массив — `print_r` внутри `<pre>` или вложенными списками `<ul>`.

### План задания 2

1. Создать папку с подпапками `Картинки`, `Музыка`, `Видео` и файлами (в именах некоторых — цифры, хотя бы один `.jpg`).
2. Написать рекурсивную функцию «папка → массив», вывести результат.
3. `.jpg` — `glob` (не забыв про `JPG`) или фильтр по `pathinfo`.
4. Файлы с цифрами — `array_filter` + `preg_match('/\d/', ...)` по имени без расширения.
5. Папки — `glob(..., GLOB_ONLYDIR)` или фильтр по `is_dir`.

## Задание 3 — функция `move()`: копировать или переместить

> Создайте функцию `move($source_file, $destination_path, $mode = 0)`, которая при `$mode = 0` копирует файл `$source_file` по новому пути `$destination_path`, а при `$mode = 1` – вырезает и перемещает его (то есть копирует в новую директорию, а из старой удаляет). Предусмотрите проверку на существование файла (в случае его отсутствия должна быть выброшена ошибка) и целевой директории (в случае её отсутствия она должна быть создана).

### `copy($откуда, $куда)` — скопировать

```php
copy("files/заметка.txt", "backup/заметка.txt");   // true
```

Создаёт копию файла по **полному пути назначения** — включая имя файла, а не только папку. Если файл с таким именем там уже есть, он будет **перезаписан** без вопросов.

Возвращает `true` или `false`. Если исходного файла нет — `false` и предупреждение (проверено).

### `rename($откуда, $куда)` — переименовать или переместить

```php
rename("files/a.txt", "files/b.txt");          // переименовать
rename("files/a.txt", "archive/a.txt");        // переместить в другую папку
```

Для операционной системы переименование и перемещение — одно и то же: у файла меняется путь. Поэтому «вырезать и вставить» — это `rename`.

Задание описывает перемещение как «копировать, а из старой удалить». Можно сделать именно так — `copy` + `unlink`, а можно одним `rename`. Результат одинаковый. `rename` к тому же быстрее: файл не копируется байт за байтом, а просто меняет место в дереве.

### `unlink($путь)` — удалить файл

```php
unlink("files/old.txt");   // true
```

Удаляет файл **насовсем** — не в Корзину. Восстановить нельзя.

Имя странное, но историческое: в Unix файл — это «ссылка» (link) из папки на данные на диске, и удаление — это «отвязать» (unlink).

Папки `unlink` не удаляет — для пустой папки есть `rmdir`.

### `mkdir($путь, $права, $вложенные)` — создать папку

```php
mkdir("backup");                              // одна папка
mkdir("Видео/2024/лето", 0777, true);         // вся цепочка сразу
```

| Аргумент | Что значит |
|---|---|
| `$путь` | какую папку создать |
| `$права` | права доступа; `0777` — «всем можно всё» (система всё равно урежет до безопасных). По умолчанию тоже `0777` |
| `$вложенные` | `true` — создать **все** недостающие папки по пути. Без него `mkdir("Видео/2024/лето")` упадёт, если нет `Видео/2024` |

Для задания нужен третий аргумент `true`: целевой путь может быть вида `archive/2026/ноябрь`.

Если папка **уже есть**, `mkdir` выдаёт предупреждение `File exists` и возвращает `false` (проверено). Поэтому перед ним проверяют `!is_dir($путь)`.

### `throw new Exception("текст")` — выбросить ошибку

Задание: «в случае отсутствия файла должна быть **выброшена ошибка**». Это не `echo "ошибка"`, а **исключение**:

```php
if (!file_exists($source_file)) {
    throw new Exception("Файл $source_file не найден");
}
```

`throw` немедленно прерывает функцию, и ошибка «летит» наружу — к тому, кто вызвал функцию. Ловят её через `try / catch`, который ты уже использовал (ЛР4, ЛР8):

```php
try {
    move("files/nope.txt", "backup");
    echo "Готово";
} catch (Exception $e) {
    echo "Ошибка: " . $e->getMessage();
}
```

Почему исключение, а не `return false`: функция не обязана знать, как показать ошибку — вывести на страницу, записать в лог или повторить. Она сообщает о проблеме, а **вызывающий код решает**, что делать. Если ошибку никто не поймал — Fatal error, и её точно не пропустят.

Подробно исключения и свои классы ошибок — в ЛР13.

### Как собрать путь назначения

`$destination_path` в задании — **папка** назначения. А `copy` и `rename` нужен путь **с именем файла**. Склеить:

```php
$target = $destination_path . "/" . basename($source_file);
// "backup" + "/" + "заметка.txt" → "backup/заметка.txt"
```

### Параметр по умолчанию `$mode = 0`

Было в ЛР8: если третий аргумент не передать, `$mode` будет `0`, то есть копирование. `move("a.txt", "b")` копирует, `move("a.txt", "b", 1)` перемещает.

Неверный режим (например, `5`) — тоже повод выбросить исключение. Удобно выбрать действие через `match` (ЛР7) с `default => throw new Exception(...)`: в PHP 8 `throw` можно писать прямо внутри `match`.

### Порядок действий внутри функции

1. Файла нет → `throw`.
2. Папки назначения нет → `mkdir(..., 0777, true)`.
3. Собрать полный путь назначения.
4. `$mode = 0` → `copy`; `$mode = 1` → `rename` (или `copy` + `unlink`).
5. Если `copy` / `rename` вернули `false` → `throw`.

### Как проверять

После каждого вызова смотри в Finder или выводи `file_exists` для старого и нового пути:

| Вызов | Старый файл | Новый файл |
|---|---|---|
| `move(..., 0)` | остался | появился |
| `move(..., 1)` | исчез | появился |
| несуществующий файл | — | — , пойманное исключение |
| папки назначения нет | — | папка создана, файл в ней |

Перемещение «съедает» исходный файл, поэтому для повторных проверок держи копию тестового файла.

## Задание 4 — все файлы во всех подпапках, по размеру, с хлебными крошками

> Рекурсивно найдите все файлы, содержащиеся во вложенных папках. Выведите их на экран отсортированными по размеру от наибольшего файла к наименьшему. При этом в скобках у каждого файла укажите хлебные крошки (то есть последовательность папок, по которой можно найти данный файл).

### Что нужно получить

```
12000 Б   song.mp3        (Музыка)
5000 Б    sea1.jpg        (Картинки › Отпуск)
695 Б     cat 2024.jpg    ()
300 Б     logo.PNG        (Картинки)
```

**Хлебные крошки** (breadcrumbs) — цепочка папок от начальной до файла, как в сказке, где по крошкам находили дорогу. На сайтах так выглядит путь вида «Главная › Каталог › Книги».

### Способ 1 — своя рекурсивная функция

Тот же обход, что в задании 2. Только теперь функция собирает не дерево, а **плоский список** файлов, и для каждого запоминает путь и размер:

```
обойти(папка, крошки):
    для каждого имени в папке (без . и ..):
        путь = папка/имя
        если папка → обойти(путь, крошки + [имя])
        если файл  → добавить в общий список: имя, размер, крошки
```

Крошки передаются вглубь, и на каждом уровне к ним добавляется имя текущей папки. Общий список удобно передавать **по ссылке** `&$list` (ЛР8), чтобы все уровни рекурсии дописывали в один и тот же массив.

### Способ 2 — встроенные итераторы PHP

У PHP есть готовый рекурсивный обход:

```php
$iterator = new RecursiveIteratorIterator(
    new RecursiveDirectoryIterator("files", FilesystemIterator::SKIP_DOTS)
);

foreach ($iterator as $file) {
    echo $file->getPathname(), " — ", $file->getSize(), "\n";
}
```

Выглядит страшно, но работает так:

| Часть | Что делает |
|---|---|
| `RecursiveDirectoryIterator("files", ...)` | умеет перебирать папку **и знает**, что внутри бывают подпапки |
| `FilesystemIterator::SKIP_DOTS` | пропускать `.` и `..` |
| `RecursiveIteratorIterator(...)` | обёртка, которая **сама** заходит во все подпапки на любую глубину и отдаёт подряд все файлы |
| `foreach ($iterator as $file)` | `$file` — объект с информацией о файле (`SplFileInfo`) |

Методы `$file`:

| Метод | Что возвращает | Пример |
|---|---|---|
| `getPathname()` | путь | `files/Картинки/Отпуск/sea1.jpg` |
| `getFilename()` | имя | `sea1.jpg` |
| `getSize()` | размер в байтах | `5000` |
| `getExtension()` | расширение | `jpg` |
| `getMTime()` | время изменения | как `filemtime` |

Это объекты и методы (ЛР13). Для лабы достаточно понимать таблицу выше. Оба способа выполняют задание. Свою функцию проще объяснить на защите, итераторы короче.

### Крошки из пути

Путь `files/Картинки/Отпуск/sea1.jpg` уже содержит крошки — надо только отрезать начальную папку и имя файла:

```php
$parts = explode("/", "files/Картинки/Отпуск/sea1.jpg");   // ["files", "Картинки", "Отпуск", "sea1.jpg"]
$crumbs = array_slice($parts, 1, -1);                      // ["Картинки", "Отпуск"]
echo implode(" › ", $crumbs);                              // "Картинки › Отпуск"
```

- `explode` (ЛР5) — разрезать путь по `/`;
- `array_slice($массив, 1, -1)` — взять кусок массива: с позиции 1 (пропустить начальную папку) и без последнего элемента (`-1` — имя файла);
- `implode` (ЛР5) — склеить через красивый разделитель.

Проверено: для файла в корне начальной папки крошки пустые. Можно выводить вместо них «(корень)».

### Сортировка по размеру — `usort` + `<=>`

Список файлов — массив массивов вида `["name" => ..., "size" => ..., "crumbs" => ...]`. Обычный `sort` не знает, по какому полю сортировать. Для этого есть `usort` — сортировка **по своему правилу**:

```php
usort($files, fn($a, $b) => $b["size"] <=> $a["size"]);
```

`usort($массив, $функция_сравнения)` берёт пары элементов и спрашивает функцию, кто из них должен стоять раньше:

- функция вернула отрицательное число — `$a` раньше;
- положительное — `$b` раньше;
- ноль — равны.

`<=>` — оператор «космический корабль» из ЛР3: возвращает −1, 0 или 1. Ровно то, что нужно `usort`.

Порядок задаётся тем, **кто стоит слева**:

| Запись | Порядок |
|---|---|
| `$a["size"] <=> $b["size"]` | от меньшего к большему |
| `$b["size"] <=> $a["size"]` | от **большего к меньшему** — как в задании |

`usort` меняет **сам массив** (как `shuffle` в ЛР5) и перенумеровывает ключи.

### План задания 4

1. Взять папку из задания 2 (там уже есть вложенность).
2. Собрать плоский список всех файлов: имя, размер, крошки (своей рекурсией или итераторами).
3. `usort` по размеру, от большего.
4. Вывести: размер (лучше в КБ), имя, крошки в скобках.

## Задание 5 — статистика посещений в `visits.txt`

> Напишите скрипт, который ведёт статистику посещений некоторой страницы. При каждом открытии страницы в файл `visits.txt` с новой строки должна заноситься информация о текущих дате и времени (новые записи внизу). На эту же страницу выведите вcю информацию из файла в порядке убывания (новые записи вверху).

### `file_put_contents($файл, $данные, $флаги)` — записать в файл

```php
file_put_contents("visits.txt", "16.11.2026 20:27:21" . PHP_EOL, FILE_APPEND | LOCK_EX);
```

Записывает строку в файл. Если файла нет — **создаёт** его. Возвращает количество записанных байт или `false` при ошибке.

Без флагов **перезаписывает** файл целиком — старое содержимое пропадёт. Флаги:

| Флаг | Что делает |
|---|---|
| `FILE_APPEND` | **дописать в конец**, не стирая. Ровно «новые записи внизу» |
| `LOCK_EX` | заблокировать файл на время записи |

Несколько флагов объединяют через `|` (побитовое ИЛИ, ЛР3).

**Зачем `LOCK_EX`.** Если два человека откроют страницу в одну и ту же долю секунды, два скрипта начнут писать в файл одновременно, и строки могут перемешаться. Блокировка заставляет второго подождать, пока первый допишет.

### `PHP_EOL` — перевод строки

Константа «конец строки» (End Of Line). На macOS и Linux это `"\n"`, на Windows — `"\r\n"`. Без него все даты слиплись бы в одну строку: `16.11.2026 20:2716.11.2026 20:28…`.

### `file_get_contents($файл)` — прочитать файл целиком в строку

```php
$text = file_get_contents("visits.txt");
// "10:00\n10:05\n10:07\n"
```

Весь файл — одной строкой. Для задания удобнее следующая функция, которая сразу разбивает на строки.

### `file($файл, $флаги)` — прочитать файл массивом строк

```php
file("visits.txt");
// ["10:00\n", "10:05\n", "10:07\n"]  — в конце каждой строки остался перевод строки

file("visits.txt", FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES);
// ["10:00", "10:05", "10:07"]
```

Каждая строка файла — отдельный элемент массива.

| Флаг | Что делает |
|---|---|
| `FILE_IGNORE_NEW_LINES` | убрать `\n` с конца каждой строки |
| `FILE_SKIP_EMPTY_LINES` | пропустить пустые строки (их может дать `\n` в самом конце) |

Проверено: без флагов в конце каждого элемента остаётся перевод строки.

Если файла нет — `file` выдаст предупреждение и вернёт `false`. При **самом первом** открытии страницы файла ещё нет — но в нашем порядке действий его создаст `file_put_contents` раньше, чем мы будем читать.

### Новые записи вверху — `array_reverse`

В файле старые записи сверху, новые снизу. Показать наоборот — перевернуть массив строк (ЛР5, палиндром):

```php
array_reverse(["10:00", "10:05", "10:07"]);   // ["10:07", "10:05", "10:00"]
```

В файле порядок **не меняется** — переворачивается только то, что выводим.

### Где лежит файл

`"visits.txt"` без пути — рядом с текущим скриптом. Надёжнее `__DIR__ . "/visits.txt"`. Файл создастся сам при первом открытии. Посмотреть его можно в VS Code — после каждого F5 в нём появляется новая строка.

### Порядок в скрипте

1. **Записать** текущую дату и время (`date` с часовым поясом) — `FILE_APPEND`.
2. **Прочитать** все строки (`file` с флагами).
3. **Перевернуть** (`array_reverse`).
4. **Вывести** списком.

Записываем **до** чтения — тогда текущее посещение сразу видно первым в списке.

Каждое обновление страницы (F5) — это новое посещение, оно тоже запишется. Так и должно быть.

## Задание 6 — поиск файлов по имени и расширению

> Создайте форму, содержащую поля `text` и `select`. В `text` вводится имя файла, из `select` выбирается его расширение. Реализуйте алгоритм поиска файлов, удовлетворяющих данным требованиям, результаты выводите на экран, если результатов нет, выведите строку «Ничего не нашлось». При этом пользователь может:
>
> - ввести все параметры;
> - ввести только имя файла;
> - ввести только расширение;
> - не вводить ничего (тогда должны отобразится все файлы).

### Форма

Как фильтр книг в ЛР9 (задание 7): поиск ничего не меняет — значит, `method="get"`.

```html
<form method="get">
    <input type="text" name="name">
    <select name="ext">
        <option value="">любое</option>
        <option value="jpg">jpg</option>
        <option value="png">png</option>
        <option value="txt">txt</option>
    </select>
    <button type="submit">Найти</button>
</form>
```

Пункт `value=""` — «расширение не выбрано». Без него пользователь не смог бы искать «только по имени».

### Четыре случая — одна логика

Главная мысль: не нужно писать четыре разных `if`. **Пустой параметр — значит «не проверять»** (как в фильтре книг в ЛР9):

| Имя | Расширение | Что ищем |
|---|---|---|
| `cat` | `jpg` | имя содержит «cat» **и** расширение jpg |
| `cat` | — | имя содержит «cat», любое расширение |
| — | `jpg` | любое имя, расширение jpg |
| — | — | все файлы |

Для каждого файла две проверки:

- имя введено **и** не подходит → пропустить;
- расширение выбрано **и** не подходит → пропустить;
- иначе — подходит.

Пустые поля ни одну проверку не провалят. Поэтому случай «ничего не ввели» сам даёт все файлы.

### Способ 1 — перебор и сравнение (надёжный)

Получить список файлов (`scandir` или рекурсивный обход из задания 4) и для каждого:

- имя — `pathinfo($name, PATHINFO_FILENAME)`, искать вхождение без учёта регистра: `mb_stripos` (ЛР9, задание 7), проверять строго `=== false`;
- расширение — `pathinfo($name, PATHINFO_EXTENSION)`, сравнивать в нижнем регистре (помни про `JPG` из задания 2).

Отфильтровать удобно через `array_filter` с замыканием (ЛР8, ЛР9 — точно так же фильтровались книги).

### Способ 2 — `glob` с собранным шаблоном (короче, но с подвохом)

Пустой параметр заменить на `*` — «что угодно»:

```php
$pattern = "*" . ($name !== "" ? $name : "") . "*." . ($ext !== "" ? $ext : "*");
// имя "cat", ext "jpg"  →  "*cat*.jpg"
// имя "",    ext ""     →  "**.*"  — все файлы с расширением
```

Подвох (проверено): `[`, `]`, `*`, `?` в вводе пользователя — это спецсимволы `glob`. Файл `a[1].txt` по имени `a[1]` через `glob` **не находится**: `[1]` читается как «один символ из набора {1}». Ещё `glob` различает регистр, и `Cat` не найдёт `cat`. Поэтому способ 1 надёжнее.

### «Ничего не нашлось»

Результат — пустой массив → `count($found) === 0` → вывести строку из задания.

### Где искать

В условии не сказано, в какой папке. Логично — в папке из задания 2 (там много файлов разных типов), можно со всеми подпапками — тогда пригодится обход из задания 4.

### Подставить введённое обратно в форму

Чтобы после поиска было видно, что искали: `value="<?= htmlspecialchars($name) ?>"` у поля и `selected` у выбранного расширения — тернарный оператор, как в выборе языка в ЛР9.

### План задания 6

1. Форма `get`: `text` + `select` с пустым пунктом «любое».
2. Прочитать `$_GET["name"] ?? ""` и `$_GET["ext"] ?? ""`, `trim`.
3. Получить список файлов папки.
4. Отфильтровать по правилу «пустое — не проверять».
5. Вывести найденное или «Ничего не нашлось».
6. Проверить все 4 случая из условия.

## Что могут спросить на защите

### 1. Чем абсолютный путь отличается от относительного?

Абсолютный начинается от корня диска (`/Users/...`) и одинаков, откуда бы его ни использовали. Относительный считается от текущей папки скрипта (`files/photo.png`). Надёжный способ построить путь — от `__DIR__`.

### 2. Что такое `__DIR__`?

Магическая константа: абсолютный путь к папке файла, в котором она написана.

### 3. Как определяется MIME-тип? По расширению?

Нет, по содержимому — по первым байтам файла. Текстовый файл с расширением `.mp3` всё равно `text/plain`.

### 4. Чем `scandir` отличается от `glob`?

`scandir` возвращает имена всего в папке, включая `.` и `..`, без фильтра. `glob` возвращает пути, подходящие под шаблон (`*.jpg`), без `.` и `..`, и умеет флаг `GLOB_ONLYDIR`.

### 5. Что такое `.` и `..`?

«Текущая папка» и «папка уровнем выше». Их нужно отбрасывать при обходе, иначе рекурсия зациклится.

### 6. Чем `copy` отличается от `rename`?

`copy` создаёт копию, исходный файл остаётся. `rename` меняет путь файла — переименовывает или перемещает, исходного файла по старому пути больше нет.

### 7. Зачем третий аргумент `true` в `mkdir`?

Создать все недостающие папки по пути сразу (`a/b/c`). Без него получится, только если `a/b` уже существует.

### 8. Почему время последнего доступа может не меняться?

Многие системы (включая macOS) не обновляют время доступа при каждом чтении — это лишняя запись на диск. Поэтому `fileatime` часто совпадает с другим временем.

### 9. Зачем `FILE_APPEND` и `LOCK_EX`?

`FILE_APPEND` дописывает в конец, а не перезаписывает файл. `LOCK_EX` блокирует файл на время записи, чтобы два одновременных посещения не перемешали строки.

### 10. Как отсортировать массив файлов по размеру?

`usort` с функцией сравнения на операторе `<=>`. Порядок «от большего к меньшему» — `$b["size"] <=> $a["size"]`.

### 11. Что такое рекурсия и где она в этой лабе?

Функция, которая вызывает саму себя. Обход папок: для каждой подпапки функция вызывает себя же, пока не дойдёт до папок без подпапок.

### 12. Что такое хлебные крошки?

Цепочка папок от начальной до файла: «Картинки › Отпуск».
